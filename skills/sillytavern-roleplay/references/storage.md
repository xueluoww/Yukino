# 存档操作

`tavern.py` 只读写明确的资料库和用户提供的输入/导出文件。它不访问网络、不调用模型、不执行角色卡脚本。

默认库 `Documents/Codex/roleplay-library`：cards/ 保存角色，sessions/ 保存各条独立剧情。卡片 ID 由名字与内容摘要组成；中文名默认使用 character 加摘要，名字可用于查找。重名时使用 ID。已存在同 ID 的不同卡片会拒绝导入；使用另一个 `--id`，不覆盖。

角色记录可保存 aliases，`import "文件" --id "角色ID" --alias "中文名" --alias "昵称"` 登记；同 ID 且同内容再次导入时只合并别名。名字与别名均按不区分大小写的完整文本查找。多个角色使用同一别名会提示歧义，使用 ID 指定，不任意挑选。角色及别名保存在共用库，所有能访问该目录的本地 Codex 聊天都可读取。

每个存档保存创建时的角色卡快照，所以日后重新导入新版卡片不会悄悄改变旧剧情。用户要求给旧存档换设定时，应另开剧情或明确商定迁移方式，而非手改快照。

## 回合文件

用 UTF-8 JSON 文件传递，避免 shell 引号/反引号/美元符号把对白误当命令。示例：

```json
{
  "turn_id": "turn-0001",
  "expected_revision": 0,
  "user": "我把伞放在门边，问你那本书的事。",
  "assistant": "（林灯抬眼看了看门边的伞。）“先擦擦头发吧。你问的是哪一本？”",
  "update": {
    "scene": "雨夜，旧书店柜台旁，开始谈论旧书。",
    "summary": "玩家来到旧书店避雨，林灯留意到玩家在寻找一本书。",
    "facts": {"umbrella_location": "门边"},
    "relationships": {"林灯与玩家": "初次见面，略有好奇"},
    "memories": ["玩家在雨夜来店里寻找一本书。"]
  }
}
```

update 可省略。summary/scene 替换；facts/relationships 按键合并；memories 追加去重。助手自己推测的秘密或玩家尚未做出的选择不要写成已确认事实。需要移除错误事实时显式把那个键更新为 null，并在新 summary 中说明修正；null 不应继续当作有效事实。

prepare 返回 revision，commit 必须带这个整数。已经保存的同一 turn_id 和完全相同内容再次提交会返回 already_saved，不重复记账；同 ID 不同内容拒绝。start 的开场已保存为 opening，不能再以一次用户回合重复保存。

stop 将剧情暂停；resume 恢复并返回上下文。它们会增加 revision，暂停期间 commit 拒绝。可以在有多个存档的库中自由选择继续哪条剧情，但不要自动切换其他聊天正在玩的存档。文件更新使用独占写锁和原子替换，避免静默丢失更新。异常退出留下锁文件时先检查是否还有写进程，不能不经检查移除锁。

会话完整对白保存在存档中，prepare 只返回最近六个回合、摘要、事实和关系；摘要需要随剧情发展更新，不能永远留着开场。场景信息和已确认长期记忆比逐字搬运全部对白更有助于续接。

`export "角色ID" "新文件.json"` 导出可迁移的角色 JSON，既有目标文件不会被覆盖。这个版本没有删除/覆盖命令；用户要清理时先明确目标和范围，按普通文件操作处理。
