# 在场、感知与人物心声

适用于 v4.4 起的浏览器舞台；v4.5 补齐旁白到场与混合表达兼容。同样作为纯文字扮演的判断依据。

角色卡是人设资料，不意味着该人物始终在场。每轮先沿实际输入顺序判断时间、地点、人物进出、距离、声量、遮挡与已建立的电话/消息联系，再书写回应。语言前缀表示发声，并不指定听众；动作和环境不是说给人物听的话。自言自语和玩家内心没有默认接收者，独处后的下一条普通语言也不自动传给上一位人物。

一个动作可能跨几个阶段。例如玩家离开房间并前往操场，原房间的人能看见离开的部分；目的地、途中行为和到达后的自语不因此成为其知识。即时变化则按当时的在场和观察条件生效。世界资料、全局剧情摘要和导演看见的整条输入，不等于每个人物都知道。不要为填满回合让人物擅自跟随或瞬移，不无故切到离场人物的房间和心声。没有交谈对象时，可以用玩家视角的环境旁白延续故事。

浏览器回复包含 `scene_state`：最终玩家地点、在场 ID、实际远程联系、到场依据，以及每个输入片段的 `input_events`。事件的接收者须配有自己的 `observations`，其中 `observable_excerpt` 只截取能实际看到/听到/读到的输入原文部分；离场观察者不能记录后半段目的地。每帧 `stage` 分别说明当前地点和在场人物，`reaction_to` 表示实际回应了哪些输入片段。主动发言用空数组，不能用它掩饰对未听见自语的回答。

引擎校验人物身份、输入对应关系、局部观察、在场、远程联系和回应对象；校验失败不提交剧情，DeepSeek 可进行一次格式/语义修正。确有观察或收到的话才进入相应人物的知识记录；同场可听见的 NPC 台词也进入现场人物记录，心声不进入别人的知识。人物在远处可以经明确电话/消息交流，但不会因通话显示实体立绘。

事实字段随当前分支原子提交：`browser_scene_state`、`browser_actor_locations`、`browser_actor_knowledge`、`browser_inner_thoughts`。新故事不会继承其他周目数据，回溯从节点快照继承当时的状态，不把之后获知的内容带回去。旧档没有这些字段时仅作不确定、只读推断；显式离场/自语会清除旧人物，不改写历史存档和对白。新回合开始保存明确状态。

UI 按每帧实际在场状态显示立绘；无人处不继承上一位人物的脸。跨地点的前后分镜可分别复用旧背景和新背景，尚未生成的新背景继续采用已有转场反馈。人物心声使用 `thought` 分镜，放在右上角“心声”小窗口，按人物和当时场景查看，可展开/收起。主对白和新回合回看不混入心声文字；读取心声只查看当前存档，不请求模型。

心声窗口可以保留此前在场时已记录的心声，并标注原场景；人物离场后不继续凭空生成其远处心声。模型不必每轮产生心声，也不能把玩家未提供的内心写进去。玩家可见简介继续仅介绍人物，感知审计、判断标准和内部字段不显示为游戏旁白。

人物登记须发生在实际被看见或走近的分镜，不以开口为前提。旁白分镜同样填写 `stage.present_actor_ids`；`arrivals.evidence` 描述本轮真实出现或接近的依据。已有角色使用剧本内完整 ID；可唯一匹配的姓名、别名、卡片 ID 和末尾短 ID 由引擎归一，重名或无法确认的身份不能借用别人的脸。未导入的临时人物可以在 `arrivals` 同时写真实 `name`、同名 `actor_id` 和包含姓名的到场依据；引擎登记稳定的临时身份，即使本轮没有对白，也保存到当前分支。没有该人物画面时保持缺省，不套用主角色图。

输入前缀表示分组，仍须理解其中实际发声的部分。动作里的明确“说、问、应”等行为和引号内台词可以形成局部 `hear` 记录，只保留真正说出的文字；准备说、心里想、未说出的目的地不能当作声音。模型引用原文时的引号宽度和空白差异可还原为原文切片，改写和增加信息仍会拒绝。观察记录与重复的接收者列表可一致化；空观察占位不会变成人物知识，主角不加入 NPC 列表。

到场数组遗漏时，只从本轮明确的环境出场或实际在场分镜的到场叙述补齐依据，不从传闻、回忆或推荐选项补齐。旧档已叙述远处出现但没登记人物时，读取阶段只将它提供为当前地点的 `nearby_encounters` 候选；须真正走近后再登记在场，不预先认定已听到发言。对于自身登场后的主动招呼，可纠正误填的环境事件回应索引；对未被听到的台词和自语不使用这种处理。同一房间的时段标题或门口描述变化不当作瞬移，跨地点的感知约束仍然生效。

`input_events` 对应输入框实际解析的 parts，一个动作片段内的台词与动作可用多条观察记录不同感官，不另造输入序号。单个 part 被模型拆成多事件时，引擎合并记录、映射回应索引，再逐条执行原文及感知校验；私语不会因为合并而变成可听的台词。看到转身或走向楼梯不代表知道后续打算回家；视觉记录截掉明确的未发声计划或内心片段。


4.6：hear 也可记录真实敲门、脚步或铃声，动作只抽取实际发声片段，不将后续意图和环境说明当作语言。stage 与 scene_state 可用 visible_actor_ids 表示能看到的人；隔门声音可交互但不必可见，明确墙体遮挡时不能展示屋内人物立绘或获取对方不可知心声。不可见人物不随玩家位置移动；完整通过感知检查后才提交回合。


v4.7：输入区新增“内心”按钮和【内心】/内心：前缀，解析为 thought。此输入没有 NPC 接收者；主角已提供的内心保留在玩家输入，不由模型另写主角心声分镜。识别“我想道”“我心里暗暗想到”等混合表达；其他人物只感知其可观察部分。NPC 的心声仍须来自当前可见人物，存入心声窗口，不广播给其他人。

多人场景无需全员轮流答复玩家。按人物性格、目标、距离、声量和实际对象决定谁主动发言、互相接话或旁听。dialogue 可填写 audience_ids（确实听到/收到的 NPC），私下低语、远程、远处必须说明听众；一般近距离同场可以省略。reply_to_frame 引用此前同轮 dialogue 的 frames 索引，引用者须实际听见它；不能引用未来分镜或未听见的话。reaction_to 仍只表示收到的玩家输入 parts 索引，不用它代替 NPC 之间的接话。输入感知及 dialogue 听众分别写入分支人物知识；没有实际互动的旁听者不自动加好感。

等待状态使用当前确认的在场/联系和本轮输入，而非最后一个立绘或角色卡锚点。离场、内心、自语和无对象动作采用中性的故事等待表现，不显示离场人物正在回应。人物名与思考表情只用于确定的当前可能回应对象。
