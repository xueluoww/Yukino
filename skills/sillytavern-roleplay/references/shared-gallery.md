# 剧本共用图库和三类预测

浏览器 4.6 使用 `browser/shared-gallery.json` 记录每个剧本已采用背景与交流画面的并集，不收录立绘或未使用预测图。图片仍位于 `browser/assets`，各档只保存 `facts.browser_gallery_refs` 引用；画廊只展示当前档已发生的画面，回溯快照只继承当时引用。共享图片不能共享剧情、秘密、关系、摘要或好感。

背景按剧本、美术版本、地点、时段、天气、季节、布局与状态匹配。`visual.background_identity` 使用 `location/time/weather/season/layout/state`，时间、天气与季节取 Schema 枚举；布局一般为 `standard`，状态一般为 `normal`，特殊状态使用短键如 `door-open`。不把描写长句或标题当键，不为复用改写当前剧情。未知的旧图片保守匹配，不把缺失条件当万能匹配。交流画面额外核对具体可见事件、人物身份、外貌、服装、表情和主角外貌；同地点不足以复用。

创建剧本时可在世界观设置：

```json
{
  "visual_revision": "school-anime-v1",
  "visual_locations": {
    "clubroom": ["侍奉部活动室", "侍奉社活动室"],
    "playground": ["学校操场", "操场"]
  }
}
```

`visual_revision` 是美术兼容版本，改人物展示年龄、好感预设或目录导入次数时不要变；世界建筑或画风实际改变时更新。地点别名避免同一地方换名称就重复生图。未配置版本时系统按背景与地点设定生成兼容范围，不同剧本始终隔离。

每棵存档树分别限制背景 2、立绘 3、交流画面 1 张。三种互不借用名额，开子分支不增加额度。失败和未用候选仍占位，只有该树实际采用候选才释放该类一个名额；再次查看、恢复、同树复用不会反复释放或补图。实际回合后才规划，已有常用表情足够时允许立绘空槽，不画重复表情凑数。

预测器通过独立 Flash 连接得到当前推荐文本、在场人物、可用服装键、已有表情及现存候选。立绘 `appearance` 使用 `school-uniform` 等服装键，外貌留在提示词；不能用整段外貌当服装键。交流画面填写实际入镜 `participants`，不自动加入主角色。它只对某个当前推荐行动做假设，实际采用须核对分支、上一节点、原样选择、场景条件、事件和入镜人物。`prepared_visuals` 提供已备候选标识，模型不能为了采用图片强迫发生某段剧情。

相同素材的在途请求合并成一个物理生图任务，各存档树的预约都会收到结果；一棵树采用不会替另一棵释放额度。采用后其他预约改为引用正式图片，保留其自己的占位直到实际使用。候选采用与画廊解锁发生在剧情提交成功后，失败回合不会消耗或解锁图片。

原生生图服务保持常驻，背景、立绘、交流画面的身份参考仍按原流程准备。预测决策写入各 root_id 的 `diagnostic.json`，包含每类剩余额度及跳过原因，技术诊断不放入人物对白或游戏等待文案。

4.6 的一次性迁移为旧候选修正服装标识与图片键，保留已画图片和占用名额；例如居家便服归到 `casual`，不会冒充制服。旧预测可在真实出现对应服装和表情后被采用。迁移先备份，不通过删除未用图来滚动刷新预算。
