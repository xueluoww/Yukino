# 剧情插图

## 判断时机

每轮先确定角色回应和实际发生的剧情，再判断插图能否增加叙事体验。适合的画面应有明确的视觉焦点，且具备值得留存的情节、情感或氛围价值；不要求同时满足所有条件。可考虑：

- 关键事件、选择的结果或冲突已经落定，画面能让玩家感受到这一刻的分量。
- 信任、距离、依赖、释怀等关系或情感出现实质变化，并能通过表情、姿态或空间关系表现；一句客套或例行脸红通常不足以触发。
- 光线、天气、景物与人物状态形成独特氛围，即使剧情平静，也值得停留观看。
- 新场景首次展开、重要人物登场或有意义的物件出现，插图能建立空间感或突出叙事线索。
- 某个细小日常瞬间具有鲜明的人物特点、象征意义或余韵，适合成为本段故事的纪念画面。

这些是判断依据，不是关键词触发器或封闭列表。普通问答、过渡动作、重复构图，以及只有抽象讨论而无清晰画面的回合，通常继续文字即可。结合最近插图判断新画面的独特性和节奏；不要为了凑频率增加事件，不在连续回合重复同一情绪。默认一个合适的回合生成一张，用户明确要求时再调整。开场也按同样标准判断，不强制配图。

## 内容与连续性

以角色卡、当前存档、已触发世界书和本轮确定的内容构建提示，明确人物外貌、服装、表情、动作、场景、构图、光线和氛围。动作与表情要符合角色当下的情绪强度，避免把克制的关心画成夸张亲密。

沿用本段剧情已建立的外貌、服装、道具、画风和人物相对位置；有可用的角色参考图或本剧情插图时，按图像工具规范作为参考。只有 JSON 人设时按文字生成，不假称有头像参考。用户未指定画风时，选择与角色及世界观相符的叙事插画风格，并保持后续一致。

玩家外貌未设定时采用第一人称视角、背影或不含玩家的构图，不自行确定其性别、容貌等身份。画面只表现已经确认的动作和关系，不替玩家作出选择，不把猜测、未触发的秘密或未来剧情画成事实。装饰细节可以合理补充，但不改变剧情。

## 生成、展示与记录

首次实际生成时读取可用的 imagegen 技能，优先使用内置 `image_gen` 工具。决定配图后直接执行；文字模式可用简短场外提示；浏览器模式通过舞台的过渡状态反馈，避免把生成信息或提示词放进人物对白。成功后在对应回合旁展示实际图片，保持文字回应完整，图片不替代角色对白。

持久会话先完成生成，再按原有 revision 与 commit 流程保存将要发出的文字及图片关联。有可用本地文件时，把选定图片复制到本次存档所属资料库的 `images/<session_id>/`，使用不覆盖的文件名；正文用绝对路径 Markdown 引用，在 `update.facts` 中以回合唯一键记录文件路径、场景简述和延续画风所需的视觉信息，沿用现有存档格式，不添加未经支持的顶层字段。有实际生成结果但无法取得可持久化文件时，仍展示结果，简短说明图片未保存，不虚构路径或声称已经存入资料库。生成的装饰细节不因此成为剧情事实。

临时试聊仅在当前聊天展示并参考图片，不调用 commit，也不为图片新建剧情存档。用户关闭配图或退出扮演时立即停止；用户说“只出图”“少出图”或指定画面时尊重其本轮意图。

工具不可用或生成失败时，继续文字剧情并简短说明本轮未能出图，不用图片占位或假装成功，不自动改用需密钥的 API、付费替代或安装服务。图像生成不能阻止正常对话及文字存档。
