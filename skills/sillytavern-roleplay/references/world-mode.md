# 世界模式作者接口

世界模式已接入正式技能供试玩，公共项目名称仍为 Yukino 0.8。玩家入口、春物特殊卡和旧档兼容见 [试玩说明](world-playtest.md)。下文是显式事件剧本的低层协议；已有剧本可由 `world_defaults.prepare_world` 在新存档开局构建默认数据，无需把运行时系统写入剧本。

地点探索、显式地图入口与人物日程是本轮**工作副本试验接口**，尚未正式安装。详见 [地图](location-exploration.md) 和 [日程](npc-schedules.md)，仅对显式启用开关的新世界模式存档生效。

## 1. 同一剧本，两种模式

在世界观对象中添加：

```json
"world_modes": {
  "version": 1,
  "default": "sandbox",
  "enabled": ["sandbox", "world"]
}
```

世界模式还需 `event_system` 声明地点、路径耗时、开场位置、物品实例与作者特殊事件。沙盒新档的冻结快照会去掉事件执行器；世界新档保留它。`POST /api/start` 可带 `game_mode: "world"`，也可在实验页面选择。这个参数只对新存档有效；读取、导出、分支与回溯继承原档的模式，不提供热切换接口。

旧版事件实验未声明 `world_modes` 的剧本保持 `legacy-event` 行为，便于回归验证。没有事件结构的旧剧本仍走原沙盒管线，不能直接选择世界模式。

## 2. 目标卡集

在 `event_system` 内添加：

```json
"goal_sets": {
  "version": 1,
  "generation": "shell",
  "max_active": 2,
  "max_pulses": 12,
  "windows": [
    {
      "id": "afternoon",
      "start": 900,
      "end": 1140,
      "actors": {
        "a": [
          {
            "id": "find-book",
            "kind": "obtain",
            "target": "rare-book",
            "title": "寻找绝版诗集",
            "probability": 0.7,
            "priority": 50,
            "deadline_after": 120
          }
        ],
        "b": []
      }
    }
  ]
}
```

时段是故事日内的分钟，不能重叠；目前最多 8 段，每人每段最多 3 个候选。`actors` 明确写出人物时，作者内容优先；空数组表示这一段不补默认目标。没写的人物由壳补候选。`generation: "model"` 可调用下面的独立模型接口；默认 `shell` 不强制消耗启动时的模型请求。

目标集保存为各人物私有的 `goal_set` 状态卡。按存档种子、人物、故事日、时段与候选 ID 抽样一次；抽中但暂时没有容量的候选留在队列，不反复抽签。每次至多启用一个候选，每人最多 1–3 个活动目标。已启用的候选不重复启动；已经开始的目标可以跨时段继续。

`probability` 是开始倾向，不是成功率。角色愿意找书不代表书一定存在、店一定开门。承诺与期限仍要由存档中的实际目标/计划状态处理，不能随机抹掉。

## 3. 保留的模型生成接口

`skill/scripts/goal_sets.py` 提供：

```python
goals = generate_goal_set(transaction, actor_id, window, gateway)
```

该接口只返回候选，不直接写状态。`gateway.ask(role, instructions, payload, max_tokens)` 的请求角色为 `goal-generator:<actor_id>`。调用方随后通过 `validate_goals`、`bootstrap`、`select_goals` 存储及启用。后续可以替换模型适配器，不必改目标执行器。

输入仅包含该人物的静态性格、自己可见的动态卡、实际听到的语言、公共地点和可识别目标；不包含完整旁白、其他人物秘密、玩家内心或兄弟分支。输出为 `{"goals": [...]}`。模型不能返回代码、effects、任意 criteria、actor 覆盖或已完成状态。最多两次格式修正；不合格结果记录诊断并明确使用壳回退。网络错误保留为错误，不假称模型已生成成功。

## 4. 壳负责的完成判据

|kind|target|判定|
|---|---|---|
|obtain|设定集物品类型 ID|本人确实持有该类型、数量大于零|
|read|具有 read 能力的物品类型 ID|目标开始后，本人通过实际阅读生成新的知识版本|
|visit|声明的地点 ID|本人实际抵达并进入；还在路上或关门在门外都不算|
|inquire|人物 ID|目标开始后，本人实际向此人提问且收到对自己说的答复；表示完成询问，不代表得到正确线索，更不代表找到了物品|
|rest|省略|本人实际开始休息且连续经过至少五个故事分钟，中途活动会重置|

目标文字不扩展这些判据。比如“到书店找到绝版书”不能只用 visit 并宣称全目标完成；应拆为 visit + obtain，或由作者玩法模块提供相应结构化结算。复杂委托、战斗、经营等继续使用剧本携带的玩法模块，不能靠模型临时制造新的壳权限。

## 5. 语言、动作和动态状态

语言由模型演绎；基础卡执行实际动作。语言检测器区分即时行为、请求、未来计划、条件、过去描述与内心。玩家“我已经替他拿到了书”不会创造书或改对方背包。

实际被指向且听到请求的人物，可以通过 `goal-reaction:<actor>` 提出 keep/adopt/decline/defer。壳检查逐字语言依据、目标对象权限、容量和明确的拒绝；通过后也只增加这个人物自己的目标，执行时还要物理校验。旁听不自动受托，离场人物不接收请求，人物可以拒绝、保持手头工作或稍后考虑。

静态角色卡保持不变；目标、知识、关系、位置、情绪、计划、活动耗时都写入各分支的动态状态卡。作者特殊事件仍通过已校验接口触发，物品具体内容来自设定集，物品规则与基础动作词表由壳维护。

## 6. 活动与边界

人物每次依据自己的目标、局部视野、已知线索和失败反馈规划一个动作，壳执行并记录实际结果。移动要走路径并等待抵达，关闭的地点不能当作已经进入；阅读和休息与其他人物活动并行，不额外占用玩家的时间。

长等待分段推进人物活动，单回合默认最多 12 个规划脉冲，防止无限模型调用。超出预算的时间继续结算已安排事件、到达与期限，并记录 `simulation_gap`；不能声称这段所有自主活动都被完整模拟。世界时间随实际行动推进，页面静置不按墙钟无限运行。

实验当前最多 8 个 NPC，并非已验证大规模开放世界。目标反应与文学表达仍使用现有模型；独立验证模型接口留待后续，不宣称已解决一切语义幻觉。

玩家可以拒绝、独处、改用别的方法。事件不自动替玩家接受任务；后果必须来自既定状态、期限和行为。预制主线可有明确问题和收束条件，自由故事不能被强行推回唯一方法。

## 7. 查看与复现

实验主界面及游戏内已有事件入口：默认主角事件，可切换世界事件。后者是读者视角，查看或导出不会令主角和 NPC 获得这些知识。

完整原创示例是 `cases/world-mode.json`。回归命令为 `python -B -X utf8 tests/test_world_mode.py`，综合校验为 `python -B -X utf8 tests/verify_workcopy.py`。真实实验工具只在内存读取现有加密本地配置，不复制配置，不使用正式私人存档。报告说明已验证范围、成本和未解决问题。
