# 世界模式试玩

这次把实验世界模式接入原技能，公开项目名称仍为 **Yukino 0.8**。内部运行时版本为 `5.7.4-world-trial`。

地点审查同时读取当前真实地点与最近同场人物实际说过的话；不会把“教室”直接匹配成另一间空教室。明确“自己班的教室”绑定冻结主角卡的 classroom_id，指代不明先澄清。不能把“看书”替换成“读笔记本”。这些检查属于壳，不要求作者增加新模块。

同一小房间的真实到达必须呈现简短可见提示，未知姓名仍用泛称，不透露目标或强迫交谈。地点可选 encounter_scope=room/area；未写时壳按现有地点信息作保守分类。操场等大区域不因共用地点 ID 自动生成到场提示。旧存档的错误动作不会被展示修复悄悄改写；需要从错误之前的脉络节点另开分支。

脉络与自动存档节点按实际发生的行动或话题命名，地点 ID 转为名称；旧“世界里的下一刻”采用只读标题恢复。自定义存档名称优先显示，最近进度另作说明。模型回应失败与无人听见区分显示，不以重复安静旁白掩盖故障。

本补丁修正熟悉度头像绑定，并增加 [行动审查](action-admission.md)。直接指定别人行动或超出主角能力时显示系统拒绝；拒绝不推进世界时间或 NPC 活动。模型审查与原动作解析共用一次请求，特殊能力依据当前存档冻结的主角卡并经剧本玩法接口执行。

另经独立世界存档 40 回合游玩和 8 回合复查，修正了完成已接受委托的目标绑定、交接审核故障的静默反馈，以及旁白提前执行阅读或替主角放下物品的问题。不要把这些测试对白或测试档当作玩家剧情。已完成的时段目标可以自然收束，不为制造热闹无限重发任务。

## 如何开始

用原来的一键启动脚本打开雪间，选择“春物 · 放学后的侍奉部”，点“新建存档”，在“游玩模式”中选择“世界 · 人物自主活动”，选一个自由故事开场后开始。已有存档仍按原模式运行；世界档、沙盒档和回溯分支分别保存。现有短篇预制线暂保留沙盒播放，不能在同一存档中切换。

在游戏中使用【语言】【动作】【环境】【内心】。主角只控制自己：可以问路、询问委托、拒绝邀请、等待、沿已定义地点移动、申请借阅和查看获准资料。NPC 有自己的私有目标，行动需要时间和实际条件。别人未听到的话、未看到的行动，不会因玩家输入就变成他们的知识。

## 春物的特殊卡片

这四张是为试玩设计的原创日常机会，并非原著固定情节：

| 卡片 | 出现条件 | 后续如何成立 |
|---|---|---|
| 结衣的申请单 | 玩家与结衣实际同在侍奉部 | 接受后实际取得或获准阅读申请单；不能靠“已经看过”自动完成 |
| 材木座的短稿 | 玩家与材木座实际同在走廊 | 自愿接受，申请借阅后实际阅读；可拒绝 |
| 彩加的练习邀约 | 玩家与彩加实际同在网球场 | 只是看看练习安排的机会，不把到场判成获胜或完成一整次训练 |
| 平冢老师的通知 | 玩家与老师实际同在走廊 | 获准查看通知后阅读；不自动强迫玩家接任务 |

每张机会按存档独立、只提供一次。NPC 依性格和时段有校园活动倾向，受阻不等于成功。开场已有在场人物优先，不能因默认日程把正在对话的人挪走。校园连通和耗时是游戏用的近似地图，未声称原著明确给出楼层、路线和教室距离。

## 壳中的基础卡库

`scripts/basic_cards.py` 是可由自由输入调用的原语；`scripts/event_schema.py` 是校验契约，`scripts/world_state.py` 和 `scripts/item_rules.py` 执行。新增敲门、坐下、起身、示意、记录文字。问候、道谢、道歉映射为说话。敲门不会自动开锁；写字需要实际持有可写物品；跨地点移动沿实际路径耗时，中途受阻不能瞬移。欺骗等组合仍由现有原语构成，不允许模型新增拥有任意执行权限的原语。

物品通用能力在壳内；笔记本、申请单、稿件和通知的具体内容由剧本提供。目标生成、执行方法库、动机、关系和隐私系统在壳内，不要求作者把系统代码塞进剧本。`goal_sets.generate_goal_set` 保留模型生成候选目标的接口；本次春物使用作者定义的日常倾向和壳的安全默认值。

## 接口与边界

主界面和游戏内均有“事件”，默认主角事件，可切换世界事件。世界记录展示已发生的事件，不改变人物可知范围。物品归属、目标达成、位置与时间以代码提交的状态为准；不能把发送成功当作有效进展。

旧剧本无需重写：`world_defaults.prepare_world` 只在新世界档构建并冻结默认数据；`world_defaults` 可选字段允许作者提供位置、连通、初始物品和时段目标倾向，设定集中 `kind:event` 的 `event` 字段承载特殊事件。沙盒不会运行这些事件。不要自动迁移旧档，不要覆盖它们的历史。

这是可边玩边修的试玩接入，并非长篇稳定性已全部验收。多人物和模型生成仍可能有诊断或行动受阻；保留错误记录，查看是否真正完成目标。
