# 好感度、人物态度与现实因果

浏览器按每存档、每人物保存好感度，范围 0–100，人物按所选主角的 initial_affinity 预设初始化，缺少预设才用 30。0–14 戒备、15–29 疏离、30–49 平常、50–69 熟悉、70–89 亲近、90–100 信赖。菜单“好感”和对话姓名旁的按钮显示分数、状态及本轮变化；未互动人物不提前列入关系面板。

玩家只看到好感状况。态度规则、变化依据和行为判断只提供给模型，不能出现在人物简介、旁白或对白里。

## 人物性格优先

态度变化、拒绝和同意必须通过该人物自身的性格、语言习惯、价值观、身份和既有经历表达。高好感不能把直率的人变成无原则迎合，低分也不能把开朗的人变成统一的冷酷模板。亲近可以增加关心、主动分享和坦诚；疏离可以减少主动交流、增加保留，或在有原因时表现不耐烦。程度须与人设及事件相称，不套固定台词，不无故辱骂。

人物对请求拥有自己的判断。结合可行性、双方经历、场合及自身目标，自然拒绝、犹豫、协商、提出条件或接受。突然表白、赠礼、玩家要求加分或在环境前缀里指定他人同意，都不能直接建立关系。没有已确认恋爱关系且好感不足70时，不直接接受新恋爱关系；高于70也只表示可以认真考虑，仍需真实相处与自身意愿。已有关系依当前记录，不因旧档未记录数字而自动抹去。高好感不等于恋爱、服从或攻略成功率。

物理与社会因果服从世界观：时间、路程、物品来源、能力和知识不能无依据变化。人物不知道未获知的事实，不能读玩家未表达的心思，离场人物不能凭空回应。环境设定用于场景，不能替别人决定感受、好感或同意；明显矛盾须自然澄清。

## 同一回合评估与提交

使用现有 Flash 回应请求，不额外调用打分模型。隐式 context.affinity 提供分数、态度及社交原则，人设与关系仍取当前剧情。模型先评估本轮实际互动，再生成符合人设的反应与 affinity_changes。每项为 actor_id、整数 delta、简短 reason；无变化用 []。

一般变化 ±1–3，普通回合服务端最多 ±5，真实重要转折最多 ±12，最终限制0–100。同一人物只采纳一项，只改本轮确实互动的出场人物；不改玩家、未知身份或离场人物。缺失或错误元数据忽略，不丢弃有效对白。不能从预测素材、未选行动或未来事件加分。

browser_affinity 是引擎保留事实，不能由模型普通 facts 覆盖。分数与剧情在同一次 commit 写入；失败或版本冲突不改变分数，同请求重试不重复加分。节点快照包含当时好感，回溯只继承选定节点及以前的数值，父档、兄弟档隔离。手动另存延续当前数值。旧档首次读取不重写文件、不根据旧对白猜数字，之后真实回合才提交记录。

逻辑与人物表达由模型生成，需要实际回合验证，不能仅凭提示词声称所有未来回应必然正确。测试只用公开整理卡或合成人物与输入，不向外部重放用户私有旧档。


## 剧本初始关系的导入

人物设定卡可加入 `initial_affinity`，以主角 ID 为键；`default` 是其他主角的基线。例如：

```json
{"age":"16岁（高二）","initial_affinity":{"hachiman":{"score":22,"relationship":"初次见面","basis":"刚在侍奉部初见，尚未建立信任。","version":2},"default":{"score":24,"relationship":"尚未相识","basis":"按此人物面对陌生人的性格处理。","version":2}}}
```

score 是 0–100 整数。basis/relationship 只进入模型上下文，不进玩家简介；公开 age、性格简介与 biography 仍单独填写。分数是剧本作者的设计判断，不是原作公布的数值。主角 ID 精确匹配才使用其原作关系，换主角不能继承兄妹、师生或救狗经历。

春物第一季开篇预设：雪乃22、结衣48、小町92、平冢静68、材木座56、户冢36、叶山34、沙希24、优美子20、户部28、海老名30、阳乃30、彩羽30。主角自身不是好感对象。小町的高分是亲情，平冢静的高分是师生关怀；未知人物不提前相识，一色不继承第二季事件。结衣的救狗背景不等于八幡此时知道狗主人，也不自动建立恋爱关系。

年龄采用第一季开篇学年：高二16岁、高一15岁、小町初三14岁；阳乃标为19—20岁的大学生；平冢静明确成年，准确年龄未公开，不编造数字。第一季人物与剧情参考 [TBS 人物介绍](https://www.tbs.co.jp/anime/oregairu/1st/chara/) 和 [TBS 分集简介](https://www.tbs.co.jp/anime/oregairu/1st/story/)；季内过生日并未自动更新静态图鉴。

用户明确要求修正已有预设时，先备份并迁移当前档及全部节点快照：新分数=新基线+(旧分数−旧基线)，限制0–100，保留原因、实际互动、对白与记忆。给记录保存 base_score 与 seed_version，避免重复迁移反复加分。不能用当前档的数值覆盖更早快照。普通重新导入仍只影响新档，不自动执行这类迁移。
