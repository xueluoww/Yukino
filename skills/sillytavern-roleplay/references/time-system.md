# 剧本时间接口（引擎5.5）

时间运行器属于壳，普通剧本只在 `world.time` 填少量数据。导入时缺省配置自动使用标准规则，兼容旧 `calendar` 字段；无需新增必填文件。`create_script.py` 生成配置与可读README。特殊时间逻辑可通过现有世界玩法模块接口随剧本携带。

## 标准配置

```json
{
  "time": {
    "version": 1,
    "start": {"date": "1800-04-01", "minute": 960, "label": "春季开篇"},
    "era": {"label": "1800年", "knowledge_cutoff": "1800-12-31"},
    "durations": {"speech": 1, "thought": 0, "action": 5, "environment": 0, "travel": 10},
    "max_turn_minutes": 10080
  }
}
```

全部子字段有默认值。`start.date` 省略/null表示未知公历日期，`label` 描述**起点**，不伪造年月日；相对第几天与时刻继续推进。公历日期使用Gregorian规则，包含跨月、跨年与闰年。`era.knowledge_cutoff` 是普通人物知识的上限；已知当前公历日期时取两者较早者。未知年份不硬猜一个截止年。

模型的 `world_updates.elapsed_minutes` 在新时间规则中不是权威值：壳读取玩家输入前缀，计算行动成本。没有实际行动时不因模型等待/生图/阅读耗时推进；纯内心默认0、语言1、普通行动5、移动10。混合前缀取最长耗时，连续多段行动应分回合，避免一次输入多项行为重复收费。动作中的明确分钟/小时/天、等待与跨日睡眠由程序解析；“十二分钟”、阿拉伯数字和半小时可用。环境说明不等于时间跳跃。需要精确路程、工作量或其他日历显示的剧本可写自己的时间模块；标准模块不冒充完整自然语言行动理解。

玩法/预制节点用 `type=time, minutes, reason` 结算；普通规则拒绝 `date`、`minute` 直接赋值。已结算的玩法动作不再额外收取输入成本。时间、模块内部状态与回执跟世界状态一起原子提交，相同请求重试不重复推进。

新档冻结完整规则与代码哈希；更新目录中的剧本只影响新开档。原有档没有 `time_policy` 时保持旧行为与时间，不无声迁移、补日期或改历史。界面里新档只能查看故事时间，旧档保留手动设置接口。启用新版玩法另建分支仍保留原档的时间规则，不把新目录规则强塞进去。

世界观 `opening_scenes` 的开场也可用 `time_start` 覆盖起点（例如黄昏开场18:00）。预制线的可选 `time_start` 与 `time.start` 同格式，只在首次开线时设置；例如终卷改编从三月开始，不继承第一卷开篇时节。进入/退出自由活动不重置时间；回溯恢复节点快照。

## 日期事实与人物例外

设定卡的 `temporal` 可包含：

- `available_from`：事实首次可知的公历日期。
- `available_day`：相对于该存档起点的可知日，正整数。
- `available_until`：人物最后可以在场的日期，不抹除历史知识。
- `aliases`：需一起检查的事实名称与别名，最多30个。

人物卡可有 `knowledge_origin: {"date":"2025-01-01","reason":"从2025年穿越而来"}`。来源时间只给本人开放历史知识，不允许该人物提前出生/到场，也不让整个世界改时代。未来技术、战争等关键知识应登记为带时间的规则/事件卡；相对时间剧情可以只用 `available_day`。

壳在注入上下文前过滤普通人物不可用的卡片，给例外人物单独提供可用知识范围。生成后核对对白、旁白、摘要、事实与记忆中的登记名称，违规只进入现有一次修复流程，不保存越界内容。当前日期宣称超出时间上限也拒绝；合理的未来预约不作为已经发生的历史事件。

**边界**：日期状态、登记事实、人物出场条件是代码检查；未登记的历史暗示、隐喻、改名或任意自然语言知识无法靠有限规则完整证明。说明中不能承诺“任何句子都绝对没有时代错误”。非公历显示、完整历史知识库、跨人物授课后的细粒度知识传播不由标准模块自动实现。

## 可选代码模块

模块仍遵循 [gameplay.md](gameplay.md) 的 `python-restricted-v1`：无网络/文件权限、限定时间与资源、随存档固定哈希。配置 `time.module_id`，同包 `world_gameplay` 必须包含该模块。导入校验会试运行初始化与0/10分钟推进；旧代码不认识协议时明确拒绝导入，避免游玩时才卡档。

1. 普通 `initialize` / `view` / `context` 必须返回正常玩法格式；时间模块可显示空卡片/空操作。
2. `time_initialize` 接收 `context.calendar/time_policy`，返回 `{"state":{...},"effects":[]}`，只初始化时间模块内部状态。
3. `time_advance` 接收相同上下文与 `event.minutes/reason/parts/scene`（玩家输入片段与原地点，由壳提供），返回 `{"state":{...},"effects":[],"elapsed_minutes":10}`。
4. 壳检查整数非负、上限、无递归效果，再按标准分钟轴推进，保存单独的 `time_runtime.module_state`。自定义代码决定耗时倍率、暂停条件等；公历与相对日的底层结算仍由壳保证。
5. 模块如需穿越，必须配置 `time.allow_time_travel=true`，并在 `time_advance` 返回 `target_date`。只有受限模块可请求，玩家普通输入、模型结果与其他效果不能直接改日期。穿越本身不自动赐予人物未来知识，仍要写明 `knowledge_origin`。

最小可运行模块见 `assets/world-templates/time-module-example.json`，可将其作为一个 `world_gameplay` 描述导入。世界观配置仍在主包，模块无需访问其他剧本或私有存档。

## 春物默认剧本

自由故事起点为“高二春季·开篇四月”，公历年与具体日留空，16:00是游戏的放学后时刻。官方人物介绍确认高二阶段；四月依据第二卷位于黄金周后的卷间时间线推断，属于来源注明的推断，不能写成原作明确日期。终卷短篇单独采用“高二学年末·三月（终卷改编）”。已有存档继续沿用其原时间。
