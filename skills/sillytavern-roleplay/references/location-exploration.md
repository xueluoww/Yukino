# 地点探索与游戏内地图（世界模式可选接口）

2026-10-11。公开名称仍为 Yukino 0.8。本接口随地图评审修复同步到正式 skills；仅显式启用的新档使用，不迁移旧档。配套日程见 [人物日程](npc-schedules.md)；可导入的原创示例是 `assets/world-templates/map-schedule-lab-script.json`。

## 玩家入口

世界模式游戏顶部有显式的 **地图** 按钮；手记中另有 **地图与约定**。地图与已知约定可切换，有关闭按钮。查看不推进时间、不触发生图、不生成日程。地图只展示当前存档中主角知道的地点和通路，不展示全世界数据库。

“前往这里”“探索附近”“继续前往…”只把动作填入输入框，由玩家确认、修改或放弃。不会自动发送，也不会替玩家接受相遇人物的请求。沙盒模式不启用本事件地图执行器。

## 剧本开关与数据位置

对**新建世界模式存档**，可在 `world` 中添加以下字段：

```json
{
  "features": ["map_v1", "exploration_v1", "npc_schedule_v1"],
  "map": {"version": 1, "nodes": {}, "description_generation": "none"},
  "schedules": {"version": 1, "generation": "shell", "actors": {}}
}
```

这是字段示意，需要实际地点节点；不是完整可导入剧本。显式事件剧本也可把同样数据放在 `world.event_system` 下。顶层配置在新档编译时优先，冻结进该档；不要同时维护两个不同版本。日程可以先单独启用 `npc_schedule_v1`，沿用平面地点。只启用地图时使用 `map_v1`；启用探索还需 `exploration_v1`。不带这些开关的旧档保留原来的平面路线行为，不自动升级。

壳提供地图协议、容量、路线和生成规则，作者只需要指定自己的空间与特殊限制。父子结构表达包含，`links` 才表达通行；处于同一教学楼不能跨房间听见别人、读别人东西或瞬移。

## 节点合同

```json
{
  "building": {
    "name": "教学楼", "kind": "building", "walkable": false,
    "entry_node": "hall", "links": {}, "initial_known_by": ["all"]
  },
  "hall": {
    "name": "一层通道", "kind": "floor", "parent_id": "building",
    "encounter_scope": "area", "links": {"club": 1},
    "initial_known_by": ["all"], "expansion": "bounded",
    "slots": [{"id": "room-1", "kind": "room", "name": "一层通道旁的无挂牌房间", "links": {"hall": 1}}]
  },
  "club": {
    "name": "活动室", "kind": "room", "parent_id": "building",
    "encounter_scope": "room", "links": {"hall": 1}, "initial_known_by": ["all"]
  }
}
```

| 字段/条件 | 规则 |
|---|---|
| `kind` | region、campus、building、floor、room、outdoor、connector；包含类型由壳校验 |
| `parent_id` | 可省略；有值必须存在，无环，最多 8 层；room/connector 不继续扩张 |
| `walkable` / `entry_node` | 不可站立的容器指向内部实际入口；入口存在且可站立 |
| `links` | 有向通路，整数分钟 0–1440；双向路写两边；不凭父子关系补路 |
| `expansion` | fixed 默认不可扩张；bounded 才能使用作者预留槽位 |
| `slots` | 每节点最多 16 个，类型仅合法子级 room/outdoor；每槽有唯一 ID、固定普通名称、至少有接通当前探索点的实际链接才可发现 |
| 容量 | 已有节点与所有预留槽位总数不超过 256；模型不能增大 |
| `secret` | 不由正常邻接发现；必须另有实际可见的知识来源 |
| `initial_known_by` | 人物 ID 或 all；作者明确授予名字与路线知识；未配置不会默认全员知道全部地图 |
| `encounter_scope` | room：同小空间有到场提示；area：同大区域不强制相遇 |

新地图按总耗时选路线，并审查当前关闭/锁门状态。旧档无开关时仍按原最少边数行为，以免暗改耗时。`located_at` 仍要求精确地点相同；需要包含判断的作者事件使用 `{"within_region":["player","building"]}`。

壳预设可用 `map.preset`：`{"type":"building","id":"annex","name":"附楼","floors":2,"rooms_per_floor":2}`。支持 campus/building/home/outdoor，容量上限在 `assets/world-templates/location-presets.json`。预设 ID 不得与已有地点冲突；它生成有限通道和普通房间槽位，属于游戏近似，不能标成原著准确楼层。与已有地图连通的路线仍要明确添加。

## 探索与知识

“前往教学楼2”第一次出现，不意味着自动造出一栋楼。名字未知或歧义时要求澄清；仅探索当前位置或其包含范围内、已连到当前通行点的有限槽位才会登记新空间。每次探索耗时 2 分钟，发现入口后仍要实际走进去。模型只可补普通描述与少量别名，不能补实验室设备、道具、秘密或几何结构。

开启 `description_generation: "model"` 后每次探索最多一次描述请求、每人物每天最多两次；额度用完使用普通壳描述，**不限制玩家活动次数**。安静场景没有额外地点请求。当前版本不新增 `place-resolver` 模型接口；不明确的自由地点表达仍需玩家澄清。

地点知识有“知道名字／知道路线／到访过”区分。听见别人说名字只得名字，不得路线和访问记录。新空间在本分支是一份物理事实，其他人物必须自行获知；兄弟分支不共享登记状态。地图、事件、存档标题和旁白都使用同一有效地图读取接口。

多段旅途中，在中途小房间实际遇到新人物或看到到场/请求，可以停在该点，由玩家决定是否继续；不替玩家接受请求。地图中“继续前往…”重新规划实际路线。大区域仅同位置 ID 不强行打断。

## 当前限制

探索成功立即显示可重复引用的地名，并保存本人本分支的发现来源。玩家可说“走进刚发现的那个房间”或“进入刚才发现的那间”；只有一个最近发现才绑定，多个候选问清。不会使用 NPC 私有发现、兄弟分支或未来记录。名字未知、只知道名字但没有路线、已知路线受阻分别给出原因与下一步建议；不会因为拒绝泄露隐藏地点是否存在。

壳生成的普通槽位使用“无挂牌房间”等可区分的中性名称，不编造用途；作者明确命名保留。旧档已登记的地名不改写，旧模板占位词仅在新发现时转换，原称呼保留为别名；正式春物地图与日程仍需明确配置并开新档。

没有跳日、自动玩家日程、地图拖拽坐标编辑器、设施/书架生成或任意未知地点无限创造。多段路线中断按当前可观察事实处理，不能代替完整的自由地点语义理解。正式春物剧本没有自动开启本接口，旧档也没有迁移。
