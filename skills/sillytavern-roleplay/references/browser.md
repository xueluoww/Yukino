# 浏览器 galgame 舞台

## 入口与启动

引擎 5.0：新增“手记”（剧本自带玩法、时间、物品、事件与承诺、关系）和“管理”（名称、备注、搜索、回收站、存档包导入导出，主界面同样提供入口）。心声使用独立大页面，默认最近记录在前。剧本创建、代码模块接口、版本固定及长期记忆规则见 [gameplay.md](gameplay.md)。旧档保留原剧本快照，启用新版玩法另建分支；未设定的旧档日期不能冒充现实保存时间。

随技能提供 `scripts/galgame.py` 和 `assets/galgame/`，无需 npm、外部字体、数据库或网站部署。Python 3.10+ 运行本地服务；自然语言对白默认由常驻 HTTPS 客户端调用 DeepSeek Flash（非思考模式）；缺失素材仍通过已登录的 Codex CLI 原生生图完成，两类请求互相独立。对话并非当前 Codex 聊天的自动镜像。先确定用户要新剧情、试聊还是明确续接，并沿用本轮已经确认的资料库 root；用 tavern 的 list 查找角色，重名和续接歧义仍按主技能处理。

命令（全部使用绝对路径和参数数组，不拼接玩家对白为 shell）：

```text
python <技能目录>/scripts/galgame.py --root <资料库> --card <角色ID>
python <技能目录>/scripts/galgame.py --root <资料库> --card <角色ID> --persistent
python <技能目录>/scripts/galgame.py --root <资料库> --card <角色ID> --session <明确存档ID>
```

正常启动显示立绘角色选择大厅，不自动进入当前内存试读。大厅提供人物简介和场景简介，下一页选择继续存档或新建存档及开场场景；新建默认立即保存，试读按钮为显式临时模式。`--persistent` 预建保存开场，`--session` 仅预载明确指定的存档。默认 URL 为 `http://127.0.0.1:18765`，自定义使用 `--port`。没有导入角色时先导入，不悄悄替换角色。不要把旧存档的事实拷入新的周目。

可用 `scripts/launch_galgame.py` 代替直接启动；它支持上述 root/card/session/persistent/port 参数并隐藏后台窗口，检查 `/health` 后返回 URL。加 `--open` 用默认浏览器打开；Codex 内优先不加此选项，按 Browser 技能打开返回的 URL。已运行的舞台通过网页菜单切换剧情，launcher 不会悄悄覆盖现有会话。

启动前检查选定 URL 的 `/health` 和资料库下的 `browser/server.json`。同一资料库的已有服务应复用；端口被其他程序或另一资料库使用时选定另一个明确端口，不扫描端口或终止无关程序。Windows 后台启动使用 `Start-Process -WindowStyle Hidden`，或 Python `subprocess.Popen` 参数数组和 `CREATE_NO_WINDOW`；持续进程不要让短命工具上下文在退出时结束它。不能仅启动进程就声称网页可用：检查 `/health` 后按 Browser 技能打开并验证画面、标记为交付标签。用户关闭浏览器标签不等于服务损坏，不反复强行重开。

用户直接在网页输入台词或动作。点击对话/继续按钮或按空格推进分镜；Enter 发送，Shift+Enter 换行，H 隐藏或显示界面。提供自动阅读、文字速度、全屏、回看、画廊、新剧情、存档恢复和暂停。显式临时试读只在进程内记剧情；点击存档时迁入已经发生的完整对白，之后自动 commit，保存失败须明确显示。临时模式仍会产生工作文件和素材缓存，不把它们称作剧情存档。

## 引擎与失败处理

默认 `--provider deepseek`：固定使用 `deepseek-flash`、`thinking.type=disabled`、流式 Chat Completions 与 JSON mode，同一服务复用 HTTPS 客户端。发送当前分支的人设、命中的世界书、摘要、事实、关系、记忆和最近对白，不发送其他存档。先验证完整结构再提交；允许确定性的 JSON 字符串换行与 key/value 映射规范化，仍不合格则只重试一次。网络、认证、额度或格式失败不提交回合，不默默改用 Codex。

密钥仅在服务端：优先读取 `DEEPSEEK_API_KEY`，否则读取 `<root>/browser/credentials/deepseek.dpapi.json`（Windows 当前用户 DPAPI 加密，不是明文）。用 `python <技能目录>/scripts/deepseek_client.py --root <资料库> --configure-key` 在本地隐藏输入配置；需要当前 Windows 用户上下文。密钥不写日志、不返回网页、不放入角色卡或剧情；复制资料库时凭据目录单独排除，其他机器重新配置。

`--provider codex` 保留为用户明确选择的兼容方式，仍通过原有 `codex exec` 和已有登录生成文本。图像始终通过 Codex 原生内置生图工具，只接收真实图片路径；失败保留原画面，文字继续。没有把 DeepSeek 的文本请求当作生图请求。

`--provider bridge` 供无法使用 CLI 时与本聊天手动协同：`galgame.py --root <root> --next-request` 返回待回应上下文、schema 和 reply_path。按卡片及 schema 生成 JSON，用普通文件工具写到该 reply_path，舞台读取后仍走原有 commit。请求五分钟过期，不写迟到回复；这个模式需要 Codex 正在处理回合，不承诺无人值守自动回复。实际图像工具不可用时不要声称动态生图已经可用。

服务仅绑定 127.0.0.1，修改请求校验来源、Host 和会话 token。静态文件限于 UI 目录，生成素材限于资料库中对应图片目录；不执行角色卡脚本、HTML、外链或上传的命令，不开放到局域网或公网。存档修改沿用 tavern 的锁、原子写入、revision 和 turn_id，冲突不盲目覆盖。停止服务前检查记录的 PID 确实指向这个脚本和资料库，不杀其他 Python/Codex 程序。

## 素材库与自动切换

`assets/galgame/characters.json` 按角色 ID 管理 display name、backgrounds、background_descriptions、sprites、avatar、reference、default_appearance 和 opening。这里的资源路径为站点内部 URL，reference 为资产目录下的相对文件；不使用远程链接执行卡片内容。初始库提供雪乃的平静、温柔、认真、害羞、思考、倾听、迟疑、惊讶、低落、不悦、愉快、闭目十二种表情立绘，可由同图裁切显示对应头像；背景包括晴天侍奉部、雨天侍奉部、午后走廊和黄昏庭院。

春物扩充库位于 `<root>/browser/assets/oregairu-sprites-v1/`。结衣、彩羽、八幡、小町、阳乃与平冢静各有十二个状态；沙希、叶山、彩加、户部、材木座、三浦、海老名各有平静、温和、认真、思考四种基本立绘。新增 100 张中 87 张选自原游戏公开移植素材库、13 张用内置 image_gen 补齐；原来的雪乃十二张保留。部分状态用原游戏的视线、口型变化表现，均为不同实际图。彩加默认绿色运动装，阳乃便服、平冢静教师白外套、材木座冬装，按实际服装登记，不能给这些素材贴上错误的校服状态。

`<root>/browser/characters.json` 用准确 `card_id` 登记 `sprites`、同一人物 `avatar`、`reference` 和 `default_appearance`；资源 URL 形如 `/media/browser/assets/oregairu-sprites-v1/yui/thinking.png`。原图来源、版权状态、哈希与补画提示词保存在该素材目录的 library.json/prompts.json，并随共享数据库迁移；代码仓库的许可不等于原游戏美术的开放许可。画廊按当前剧本人物显示“姓名 · 表情”。旧设定没有 card_id 时，只在相同 world_ids 内以唯一姓名/别名绑定视觉资源，不改写该周目的快照。默认八幡外貌或主角卡明确提供 visual_manifest_id 时可绑定主角立绘；自行导入的其他外貌不会套用八幡。

新角色先按其卡片和可用参考准备匹配背景与充足表情，再交付舞台；至少覆盖默认表情、等待中的思考/倾听和常用情绪，按角色实际表现扩充，不只准备单张立绘；不要把雪乃素材用于其他角色。新素材使用 imagegen 技能与内置工具，不以 CSS 绘制人物代替角色图。立绘须透明背景，头部完整留边，保持构图和尺度便于切换；参考图只用于外貌与画风，不导入其故事关系。未设定玩家外貌时不编造其身份。

每回合生成 `visual`：background 使用稳定场景键（包含必要的地点、时段和天气差异），expression 使用当前情绪，appearance_key 表示已确认服装。语义相同的场景、表情与服装复用同一素材，不因提示词改写重新生成。新场景用 background_prompt 说明空间与氛围，新人物状态用 portrait_prompt 说明实际外貌与情绪。普通一句问候不触发换装或强烈表情；人物不在场时使用 absent。背景与立绘按实际需要分别生成；独特关键瞬间才额外生成完整 CG，标准沿用 illustrations.md。

舞台异步生成新图，完成后先加载解码，再更新对应背景、立绘及头像；期间对白继续，旧画面保留并以模糊、缓慢镜头位移与目标场景卡表现过渡；失败时恢复静止画面并提供重试。过渡不能替玩家编造行走、心理或新事件。过时任务仅进入素材缓存，不能把已离开的场景切回当前剧情。用户关闭“随剧情生成新画面”后不再提交新生成任务，已有图库仍可切换。

工作目录为 `<root>/browser/`：jobs 保存回合输入输出，image-jobs 保存生成记录，assets 保存动态素材，asset-cache.json 记录角色、语义键、提示词与实际路径。已保存会话在 `facts.browser_visual` 和 `facts.browser_latest_frames` 中保存分镜与所引用素材键；恢复时通过同一资料库素材缓存找到真实图片。CG 关联产生它的 session_id 和实际剧情节点；分支可以继承选定节点以前的 CG，不能继承原周目的未来画面。完整 CG 展开时隐藏立绘，让插图成为舞台，并保持可继续阅读。保留图片和资料库一起迁移；不要只复制 sessions 而声称插图也已迁移。临时试读的缓存不会创建 sessions 文件。

## 库的准备与验证

用户授权预建素材时，在单独测试 root 模拟常见情境，提取环境、情绪、服装等视觉需求，生成可复用素材并登记清晰的用途；不将测试对白、关系或剧情秘密迁入真实会话。不要为了素材库写“必然发生”的剧情分支。

验证可观察的效果：至少一个真实中文回合、一个缺失素材从原生生图到画面的路径、同素材复用、人物离场隐藏、试读转存档与续接，以及桌面和小屏幕可读性。校验 JavaScript/Python 语法并按 skill-creator 验证技能。图像是否成功以实际文件和可加载画面为准，不能以模型一句“已生成”作为证据。

## 跨窗口添加角色与存档

此流程属于技能能力，不属于某个聊天：任何 Codex 窗口接到“添加这张角色卡到环境”都执行以下步骤。始终优先复用用户 Documents/Codex/roleplay-library；已经指定自定义共享 root 时沿用该 root。不要默认创建项目内副本，不使用聊天 ID 作为资料库目录。重定向 Documents 按主技能处理。先查 list 和现有 browser/server.json，已有同库服务直接复用。

1. 使用 tavern import 导入卡片并登记别名；只有无有效元数据时才要求补充人设。导入成功并不自动开启剧情。
2. 读取人设、原始开场与备用开场，整理不泄露剧情秘密的中文 bio、scene_intro 和 scenarios。原卡开场按 greeting 索引引用；经用户授权的独立新场景可用 opening 分镜，且仅改变新存档的卡片快照，原始卡与其他周目不变。
3. 准备真实角色参考、透明表情立绘库与匹配开场背景；固定服装、姿态、镜头与尺度，只修改必要的面部表情；素材保存到共享 `<root>/browser/assets/`，站内 URL 使用 `/media/browser/assets/<文件名>`。不同角色按 card_id 区分，不复用其他角色外貌。
4. 在 tavern.write_lock(root) 内读取并合并 `<root>/browser/characters.json`，以 card_id 为键原子写入该角色描述，不覆盖其他角色。字段包括 name、bio、scene_intro、reference、default_background、default_appearance、backgrounds、background_descriptions、sprites、avatar、scenarios；reference 同样可使用上述本地素材 URL。素材路径不包含远程资源。运行中舞台每次读取状态会重新合并此文件，人物选择页自动刷新，不重启或打断已开的剧情。
5. 确认新角色出现在 /api/state.cards，素材真实可加载。网页只有剧本、存档、场景选择，不添加角色卡上传/导入面板。

存档使用共享 `<root>/sessions/<session_id>.json`，每个周目有独立 ID、人设快照、原始对白、摘要、事实、关系和视觉引用。角色 ID 用于筛选存档；不能仅按名字覆盖存档。其他 Codex 窗口或重启舞台后用同一 root 查询 sessions/resume 即可续接，不依赖原聊天还在运行。关闭浏览器并不删存档，已提交的完整回合留在磁盘；正在等待的回合不假称已保存。当前文本和视觉状态保持一并原子 commit。并发冲突保留失败回合文件并提示重试，绝不覆盖其他窗口的更新。

游戏舞台隐藏模型名称、任务计数、缓存和提示词等技术信息，必要反馈与剧情画面整合。发送时立即显示玩家原文，服务确认后标记送达；角色切换思考表情并有细微动态，保存前不冒称已经回应。连接不确定与回应失败保留原输入，重试复用请求 ID，避免重复写入。等待状态不写入角色事实、对白或玩家动作。主动点击存档仅在实际成功后短暂提示“已存档”，自动保存保持安静；底层详情留在 browser 工作文件中。新场景未就绪时使用转场视觉，失败提供重试，不以假进度或虚构成功安慰玩家。

## 纯音乐与播放

网页与音乐库均随技能存于 assets/galgame。music/library.json 登记五首本地纯音乐及作者、来源、许可与校验值，music/CREDITS.md 保存署名。钢琴/电钢琴适用于日常静谧、雨夜沉思、温暖互动、失落与悬疑；选曲依据当前回合人物表情、对白/旁白和当前场景，不把角色一贯冷淡当作冲突，不把历史伤心记忆当作本轮情绪。前端 music.js 自动匹配，播放器循环，切换淡入淡出 1.6 秒，自动换曲至少间隔 12 秒，避免频繁打断。仅改变视觉或表情的过时图片任务不改变音乐。存档恢复后按已恢复的场景与本轮情绪重新选曲，不依赖旧聊天。

浏览器要求用户先点击/按键才允许有声播放；不绕过自动播放限制。默认音量 25%，开关、音量、固定曲目或随剧情选择存在浏览器阅读偏好中；这些偏好不进入角色事实或玩家身份。音乐按钮一键静音，菜单提供音量、选曲及音乐库署名；载入失败不在游戏画面弹处理提示，文字仍能继续。暂停剧情停止音乐，返回选择页可恢复平静曲目。

新增音乐须读取实际来源与许可、下载并核验真实可播放音频；纯音乐不混入有声歌词，不从动画游戏中擅自抽取未授权原声。保留源音频的独立许可与作者署名，不把技能的代码许可套用到音乐。扩充 library.json 即可供其他角色共享，不将某首曲目锁死到单一角色。


## 剧情发展与分支

每轮的 story 包含本轮事件 title、beat（铺垫、发展、揭示、转折、收束）、实际重要性 milestone、未完线索 thread 与 0–3 个可选回应 choices。节点描述已发生内容；选项表示尚未选择的可能方向，不进入事实。顺着角色目标、未完线索与玩家行动推进情节，允许停留、拒绝、离场和自由输入，不强迫恋爱或照搬预设结局。关键画面按 illustrations.md 选择真实 CG。

facts.browser_story 和本轮对白一并 commit，网页“脉络”显示连续节点、关键转折、已完成的 CG 与当前可能方向。已保存节点在 browser/checkpoints/<session_id>/<turn_id>.json 留下完整快照；“从这里另开故事”使用新 session_id，继承当时的历史、事实、人设与视觉引用，原存档完整保留。旧存档的过去只从真实对白恢复为已发生片段，不补造当时的关系或快照；恢复点及以后可以保存分支快照。

## 回应效率与恢复

角色常用表情在开场预加载，缺失背景/服装/CG 异步处理，一个常驻生图进程串行处理任务，确认场景优先于排队的候选素材。默认对白使用 DeepSeek Flash 非思考模式；仅显式选择 codex 时使用当前登录模型的 low 推理子进程，不更改全局配置。上下文保留人设、命中的世界书、摘要、事实、关系、记忆与最近对白，去掉重复的界面状态和完整历史图。

很长的角色卡可在描述中提供 dialogue_profile：source_sha256 是 card_snapshot.data 的 description、personality、mes_example、system_prompt、post_history_instructions 五项以缺失值空字符串、ensure_ascii=False、sort_keys=True 的 JSON UTF-8 SHA256；description 为核对原卡后整理的紧凑人物资料，mes_example 为保留对白风格的代表例子。不得遗漏重要弱点、关系与行为边界，不把原作未来结局写成玩家既定经历。摘要只在来源完全匹配时生效，卡片更新会自动回退完整资料；原卡和存档人设快照始终完整保留。新角色导入时可以一次准备资料，不在每轮再次摘要。

速度以真实回合记录 metrics 为准，不承诺即时输出。当前收到完整回应后仍先验证并提交再展示。浏览器把未完成输入按存档 ID 保存在本地，刷新后对照服务 activity 和已提交 turn_id 恢复，绝不自动重发或把不确定输入假称保存。browser/image-tasks.json 保留图像任务与提示词，重启后将中断任务视为未完成，可在当前场景重试。

显式选择 codex 文本提供方时，子进程使用仅本次调用的 yukima 提供者别名：name="OpenAI"、wire_api="responses"、requires_openai_auth=true、supports_websockets=false。不设置新地址、不使用新凭据、不换模型，沿用 Codex 登录与官方服务，以 HTTPS 跳过此环境已确认失败的 WebSocket 重连。原生生图仍使用原有内置工具链。所用字段见官方配置参考 https://learn.chatgpt.com/docs/config-file/config-reference 。如果未来版本或用户环境不支持此组合，应验证实际错误后调整子进程，不能写入全局配置或自动换成付费 API。

更新服务前确认无对白或图像任务，并保留当前完整存档。新版可用具有相同来源/token 检查的 POST /api/shutdown 安全停止；老版需在同一操作内核实 PID 命令行属于本脚本和本资料库再停止。更新后以明确原 session_id 恢复，不另建玩家周目，不同时运行两个同库写入服务。


## 输入语义、分支树与独立记忆

网页提供“语言 / 动作 / 环境”插入按钮。服务把【语言】、【动作】、【环境】以及冒号前缀解析为 `player_input`，保留玩家原文；模型不能让角色听见行动或环境描述。明确环境设定作用于本轮场景，有时间或天气变化时交代过渡，既有记忆不回写。

每个存档自带独立的 summary、scene、facts、relationships、memories、turns，`memory_scope` 恒为本 session_id。这里已经存在独立记忆库，不引入 LexThink 的全局聊天记忆或词库。候选另存为 `<root>/browser/prediction-library/<root_id>/index.json`，只作假设视觉目录，不能进入剧情事实。旧 predictions 文件仅保留，不再用于启动预制。

`POST /api/save`：临时试读首次保存保持当前 ID；已经持久保存时，复制当前完整状态为新的子档，随后继续写该子档。自动回合 commit 更新当前 ID，不覆盖父档。`POST /api/branch` 从指定节点的真实完整快照创建新 ID，继承截至该节点的对白、事实、关系和记忆；父档和兄弟档保持原有内容，分支的未来独立。

分支元数据包含 parent_id、root_id、node_id、label、kind。主线编号为“主线”，子档形如“主线.1”，再分支为“主线.1.1”；同一父档允许多个子档，不限制为两个。继续存档与管理界面每条故事只显示起始父档；进入后打开独立横向分支页面，关闭弹窗并隐藏原页面，父档在左、子档向右展开。支持拖动空白处、底部滑条、方向键和定位最近存档，退出或 Escape 返回来源页面；点击任意节点读取该 ID，节点另有管理按钮。删除父档后的孤立子档仍展示，共同 root_id 保持分组但不伪造连线。脉络上明确显示“回溯到这里 · 新建分支”。

检查原存档 revision 后才能另存或回溯，冲突要求重载。节点快照创建后保持不变；子档只复制回溯点以前确实存在的快照，并更换这些快照的 session_id 和 memory_scope，因此子档的更早节点也可回溯。旧存档无快照的过去不假造关系或记忆；所有旧存档仍可继续。维护重启使用 `--restore-session` 读取原状态而不激活暂停的故事。

## 独立预测图库与常驻生图

前台 Flash 只生成对白和本轮元数据，`predictions` 返回空数组。新建正式剧情或完成真实回合后，另一条持久 HTTPS 连接按当前分支的已发生线索与空余名额规划未来 1–2 轮候选。既有候选不替换，不在服务启动、轮询或空闲时反复规划。预测失败不丢弃成功对白，不进入 summary/facts/relationships/memories。

每棵存档树共享预制限额：背景 2、立绘 3、交流画面 1。`preview_library.py:QUOTAS` 是默认模板。queued/painting/ready/failed 均占位；仅 used 释放同类型名额。回溯/另存不会翻倍。候选文件位于 browser/prediction-library/images，索引按 root_id 区分，在“画廊 → 候选图库”单独查看。未用图片不进入正式画廊，不自动销毁后重新填槽。

背景核对剧本美术版本及稳定地点、时段、天气、季节、布局与状态；立绘核对角色身份、外貌、服装和表情；交流画面额外核对分支 ID、上一真实节点、原样的玩家选择及背景。实际回合提交成功后才采用候选，将图片转入 browser/assets 并标记 used；失败回合不消耗候选。真实采用释放的名额，在接下来的实际回合规划时补位。没有充分剧情依据时允许名额空缺，不为填满而造事件。失效但未用候选继续占位，用户可以明确要求清理/重新规划；不能自动轮换形成无限生成。

`image_service.py` 维护一个 Codex app-server stdio 进程，初始化一次；visual thread 按分支、图类型和人物隔离，确认画面与假设候选使用不同会话。任务使用内置生图，不启动每图一次的 codex exec，不更改全局配置或改用付费图像 API。关闭服务时清理自身子进程。服务器会做本地预热握手，不因此生成图片。排队的已确认场景优先；正在生成的候选不会被强行中断。常驻只减少初始化开销，生图仍可能需要数十秒或更久。

图片提示词只存在本地任务文件，画廊名称始终为中文；旧英文提示的图片使用中文通用标题。成功文字与画面任务分开提交，图片失败或可选工作失败不能把已保存对白标记为失败。

## 多人物、世界观与玩家

导入流程见 [worlds.md](worlds.md)。每个保存点冻结 world_snapshot 和 protagonist_snapshot；旧档没有这两个字段时，使用已绑定背景及默认主角，在下一次真实提交保存在 browser_world_snapshot/browser_protagonist_snapshot，维护读取不改写对白存档。新导入资料不改写已有快照或历史记忆。用户明确要求给现有存档关联世界观时使用 attach，并重新恢复该存档。

每帧 actor_id 由后端按姓名/别名解析。设定集人物使用自己的参考与立绘；未定义人物建立当前分支的临时姓名记录，没有脸时隐藏立绘，不借用主角素材。生图任务捕获当时人物和主角资料，不在任务完成后读取另一周目的人设。头像只在同一人物没有可用立绘时显示。推荐回复带【语言】【动作】【环境】前缀，点击先填输入，仍需玩家提交。

Flash 长连接遇到可重试的连接断开/429/5xx 时最多恢复一次；格式错误先做不改变对白/事实的字段归一化，仍失败时最多修复一次。401/402 不反复请求，不切换文本提供方。字段路径与错误类别留在 browser/jobs 的 diagnostic.json，画面保留原输入与重试入口。真实 commit 成功后的可选任务错误不能冒称剧情未保存。

## 剧本入口

舞台使用 /api/state.scripts 显示可玩剧本，以世界观 ID 为 script_id。POST /api/start 可传 script_id、scenario、protagonist_id；后端解析剧本的锚点卡和设定集，使用 world.opening_scenes，不使用配角各自的 greeting 作为世界开场。配角导入的卡不成为独立剧本。旧独立角色卡仍可作为兼容角色卡剧本，新旧存档均保留独立记忆。完整导入流程见 [scripts.md](scripts.md)。

## 在场、听闻、局部观察与心声

v4.4 按回合和每帧保存地点、在场人物、接收者与实际可观察的输入片段。角色资料锚点不等于听众；语言前缀不让离场角色听到自语。动作跨地点时，原地点人物只知道看见的前半段，不知道玩家后续目的地与行为。人物知识与位置按当前分支保存，回溯继承当时记录。无人旁白不继承人物立绘；远程联系需有真实电话/消息依据。详情与内部字段见 [perception.md](perception.md)。

人物心声放右上角“心声”窗口，可展开、收起并查看当前分支已记录的心声。它不占主对白分镜，不写进新回合回看，不作为其他人物的知识；离场后不继续生成远处心声。旧档按只读推断兼容，不改写历史对白。

v4.5 登记旁白中的实际到场人物，兼容唯一姓名/别名/短 ID、同一地点的时段标题和动作内明确说出的台词；单个输入片段的重复事件会归并后重新检查感知范围。未知身份、未观察的私语和后半段目的地仍拒绝写入。一次回应最多一次格式/语义修复；语义修复同时纠正不合理分镜，不只修改字段来掩饰异地回应。失败诊断另记模型返回的身份/舞台字段，不将技术信息显示为人物对白。详见 [perception.md](perception.md)。


4.6 的剧本共用图库、每档解锁引用、三类预测规划与迁移细则见 [shared-gallery.md](shared-gallery.md)。图片共享不影响存档记忆与回溯隔离。


## v4.7 回看、导出与剧情插图停留

回看按回合倒序，每回合内部依照发言顺序保留人物姓名和旁白，不把全轮署成主角色。新回合在 browser_turn_frames 中随剧情原子保存。旧回合只读取本分支的对应快照，并核对完整对白前缀；不查询兄弟分支或补造未记录对白。没有结构记录时显示历史文本，不猜署名。传给模型的最近对白也保留真实人物姓名。

回看、脉络和心声提供文本与 Markdown 下载以及完整故事导出，具体见 [story-export.md](story-export.md)。读取心声、回看和导出均不续写剧情。

cg_cue 将插图绑定 turn_id 与素材 key。对应回合末暂停发送、推荐与自动推进，展示有动效的剧情插图等待卡；加载并成功解码后进入 CG 画面，玩家点击“欣赏完毕 · 继续故事”恢复输入。可选择先继续故事，迟到图片只加入该故事节点和画廊，不打断别处剧情。失败提供重试与继续，不无限重试。普通背景过渡和立绘补充仍不阻塞文字回合。图片就绪不重置已读分镜，读到的进度只随新回合或明确切档重置。

普通输入只调用文本回合接口，玩法操作只有玩家明确点击相应操作时才调用玩法接口；重试沿用同一请求 ID 和同一种操作，不能继承上一条已完成消息的玩法参数。HTTP 明确拒绝要显示失败原因，网络超时才保留等待确认；轮询不能把已确认的失败改成等待确认。未接受的请求原因记录在对应 jobs/<session>/<request>/rejection.json，已接受回合的失败仍见 diagnostic.json。存档外层按故事起点分组，内部用独立横向分支页面浏览，底层分支、快照和独立记忆保持原样。
