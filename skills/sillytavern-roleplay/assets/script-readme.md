# 创建这个剧本

这是一个可独立导入的 `yukima_script_v1` 剧本包。主程序负责显示、调用模型与保存；世界、人物、玩法规则属于本包。

1. 修改 `world.json`：标题、背景、开场、初始时间及可选故事线。
2. 修改 `settings.json`：人物、地点、物品与事件；人物简介写给玩家，模型约束放人物卡内部。
3. 保持世界引用的设定集 ID、主角色卡 ID 与实际卡片一致。
4. 在任意调用角色扮演技能的 Codex 聊天中提供本目录，先验证，再导入选定资料库。网页负责选择和游玩。

## 时间：普通作者只需配置

`world.json` 已有 `time`，不需要另写时间模块或安装依赖。最小写法：

```json
"time": {
  "version": 1,
  "start": {"date": "1800-04-01", "minute": 960},
  "era": {"label": "1800年", "knowledge_cutoff": "1800-12-31"}
}
```

`minute` 是午夜后的分钟数，960 为16:00。日期未知时省略 `date`，使用 `label` 描述开篇时代与季节，程序按“第几天”推进，不能把出版日或播出日当作原作日期。时代不知道就留空，不随意写知识截止日期。

默认说话1分钟、普通行动5分钟、移动10分钟、内心与环境说明0分钟，可通过 `durations` 覆盖。一个混合输入按并行行动的最长耗时计算；连续多项行动请分回合输入。用【动作】等待20分钟、休息两小时或睡到第二天明确消耗时间。【环境】不能直接跳日。玩法动作与预制节点也可通过经过分钟数推进时间。

新存档冻结规则；改剧本不会改写旧存档。回溯恢复该节点的时间、人物知识与规则版本。暂停、读图、生成回复和停留界面不推进故事时间。

## 时代知识

设定卡可用 `temporal.available_from`（YYYY-MM-DD）、`available_day`（故事相对日）与 `aliases` 登记知识出现条件。程序过滤未到时间的资料，并拦截模型在对白、旁白、摘要与记忆中使用这些已登记的未来事实。人物的 `knowledge_origin: {"date":"2025-01-01","reason":"来自未来的穿越者"}` 只给该人物开放来源时代知识；不把穿越人物的知识交给所有人。

没有具体年份的故事仍可使用相对日门槛。未知日期不满足明确日期门槛。程序能硬检查已登记事实和日期状态，不能完整证明任何自由文本都没有时代错误；对时代关键的技术、历史事件请添加带日期的设定卡。

## 特殊玩法与时间

普通剧本不需要代码。特殊规则可在 `manifest.json.world_gameplay` 引用本包的模块文件，受限Python代码与配置随包携带；主程序无需新增专用代码。自定义时间用 `world.time.module_id` 引用已导入的模块，遵循技能 `references/time-system.md` 的 `time_initialize` / `time_advance` 协议。

预制故事线可在世界观 `storylines` 中引用独立JSON，每条线可用 `time_start` 指定自己的起点；节点 `effects` 使用 `{"type":"time","minutes":10,"reason":"步行到下一个地点"}`。自由段允许玩家自行完成当前目标，收束由明确完成条件决定。

## 检查与导入

以实际技能目录和资料库绝对路径替换下列占位符；`validate-script` 不写正式库，`import-script` 才导入。

```powershell
python "<技能目录>/scripts/worlds.py" --root "<资料库>" validate-script "<本剧本目录>"
python "<技能目录>/scripts/worlds.py" --root "<资料库>" import-script "<本剧本目录>"
```

每个开场还可用 `time_start` 指定自己的起始时刻，例如黄昏18:00；与预制线相同，都只在初次开档生效。

模型Key属于使用者本地配置，不放进剧本或发布包。图片登记在选定资料库的视觉配置，准确关联人物与背景ID。现有素材要保留来源与许可信息。
# 日常结算、关系与固定事件（Yukino 0.8）

世界模式按动作步骤结算。点头、整理衣领等用已有手势接口；普通交通沿实际已知路线移动并结算耗时，不要求给公交车建物品卡。普通小额购买使用壳标准库 `buy(item, quantity)`，必须在冻结剧本声明了购买服务的实际地点进行；后续交接与消耗依然检查所有权。询问能否购买或阅读，不会提前执行。

可在 `world_defaults.daily_life` 中声明 `{enabled:true, accounting:"abstract", services:{地点ID:["daily-water","daily-coffee","daily-snack","daily-book","daily-ticket"]}}`。可选 `spending_limit` 是本档总抽象支出额度，不是活动次数限制。不声明额度时只记录日常支出，不模拟货币数量；如果本档已模拟现金，必须走实际 `commerce/pay` 交易。普通书不自动获得具体标题或正文，特殊物品仍由作者写物品卡。

壳统一治理有向关系增长。实际交接、实际完成已接受委托、真实当地共同经历才提供增量来源；不会因为玩家声称帮过忙就加分。`relation_policy` 可配置正向每日上限、同源上限、重复同类礼物上限及阶段门槛。负向变化独立结算，反复送同一类礼物默认不继续涨。自由完成的共同事件可满足阶段条件，阶段不绑定唯一剧情路线；数值不替代同意、姓名知识、隐私或人物性格。

作者的 `fixed_events` 数组声明 `id/title/description/day/minute/duration/location/participants/excluded/sources/date_basis`，可选 `schedule_override` 和 `notice_locations`。`participants` 只能是 NPC；玩家不自动接任务或被拉去现场。事件最多64项、每项最长180分钟，跨日活动应分阶段。安排按真实路径执行，普通日程可以被覆盖，但实际承诺与个人例外保留。公告只有实际在声明地点的人获知，远处的世界记录不是人物知识。

`opening_hours` 可声明 `{地点ID:[[开门分钟,关门分钟]]}`，分钟按一天0–1440计；支持跨午夜窗口。校门、房间与经营地点需要独立声明。规则关闭时不瞬移赶人，人物仍须实际离开。

地图节点可写 `name_visibility:"signposted"|"on_visit"|"hidden"` 和 `entry_visible`。默认仅看见匿名入口，不能直接知道无标识房间的功能；明确可见挂牌才获知名称并记录来源。开场 `initial_known_by` 是初始知识，不是永久保密名单。本人后来实际发现、进入或听闻仍可获得新知识；名字不等于路线。

春物原著六项固定事件及原作依据见同目录 [oregairu-fixed-events.md](oregairu-fixed-events.md)。最新模板另加42项原创校园机会，共48项；原创排期不冒充原著情节。课表、考勤、周末和假期接口见 [校历说明](../references/school-calendar.md)。模板更新只影响新导入内容及新建存档，不替换旧档冻结剧本。

日常饮用/食用支持 `eat(instance, portion:"small"|"all", quantity)`。一口是抽象小份，保留剩余量，不声称毫升；整件用完才扣数量。壳提供的水20小份、咖啡10小份，旧可食用定义缺省10小份，执行时记录剩余而不改冻结定义。少量消费只针对一件；交接保留来源与已用部分，不重复复制已用量。已经发生的旧错误消费不自动恢复。
