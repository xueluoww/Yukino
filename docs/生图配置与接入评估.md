# 生图配置与独立后端接入评估

2026-10-12，Yukino 0.9。启动页把“已有图片”“Codex原生”“独立图片API”和“可灵授权”分开，文本仍由DeepSeek处理；不安装DeepSeek Harness，不复制其历史会话，也不反代其他网页的免费账户。

## Codex入口

检测使用CLI登录退出码和原生app-server初始化、账号读取，不回传凭据或邮箱。自动配置将固定版 `@openai/codex@0.160.1` 安装到本包runtime，需已有Node.js/npm；不修改全局Codex模型配置。登录由玩家完成官方浏览器OAuth。检测、安装、登录和启用各有独立按钮，缺Node时提供官方安装入口，不能假称环境已配置。

本机已经核对Codex 0.160.1登录及服务握手。**未做试画，仍标记 generation_verified:false**。登录凭据存在不保证图片额度、模型权限或真实图片成功。[官方CLI文档](https://developers.openai.com/codex/cli/reference/)

## 独立图片API：可以脱离Codex

[ankye/dsh-image-generation](https://github.com/ankye/dsh-image-generation/tree/main/packages/tool-image-generation)将模型的绘画需求交给独立后端，返回落盘图片；它自带的通道使用兼容图片API，仍需要图片接口、模型和密钥，不是DeepSeek文本模型获得原生绘画能力。

Yukino采用这个分工思路，以Python实现适配器，无需把Harness运行时搬进游戏：

- 文生图使用 `POST /images/generations`；参考图及原图重画使用 `POST /images/edits`，多张参考图以multipart发送。
- 一次请求只生成一张；返回Base64或图片URL后验证格式、限制体积并保存真实本地文件，再接入原有图库、版本采用和回溯绑定。
- 仅文本接口不能伪装成参考图接口。需要参考图而接口不支持时直接说明，不忽略原图或人物外貌约束。
- 图片密钥单独DPAPI保存并绑定接口地址；变更地址不能把旧密钥发给新服务器，不借用DeepSeek密钥。
- 接口校验只读取模型列表，不调用生成。超时/结果不明确时保留提交记录，不自动再次扣费；若已拿到结果却下载失败，只重试下载。
- 无静默供应商回退；跳转不转发密钥；CDN请求不带图片API的Authorization头，签名链接完整保留在本地任务记录，不铺进日志或玩家对白。

24项本机假服务与配置检查通过，未用真实图片供应商试画。不能保证所有“OpenAI兼容”网关都支持图片编辑、透明背景和同样尺寸；PNG实际画质和身份稳定性必须用选定服务验证。地址应包括供应商版本前缀；只有显式本机服务允许HTTP和无密钥。

公共包的人物标签SVG是占位图，不是实际人像参考；先补真正PNG/JPEG/WebP。首次缺图可按人设描述生成，但它不能保证等同原作立绘。用图像接口不会改变人物、关系、地点或已发生剧情。

## 可灵：连接可行，自动生成尚待真实协议适配

[klingai-dev/deepseek-plugin](https://github.com/klingai-dev/deepseek-plugin)通过官方 `https://klingai.com/mcp` 和固定版 `mcp-remote@0.2.0` 完成标准OAuth；生成使用可灵自己的额度，不需要Codex，也不使用DeepSeek API Key。

本轮提供独立连接器安装与OAuth入口，授权后只执行初始化、工具发现和只读 `who_am_i`。沿用上游兼容桥接参数，UI明确这是可灵授权入口。仅保持一个属于本启动页的客户端，退出时关闭自己的进程；不调用生图、视频、素材上传或其他写操作。

**还没有启用自动可灵绘图。** 上游以实时工具schema为准；本轮没有真实可灵账号，不能猜参数、参考图上传协议、模型/额度和任务返回。后续完成自动接入至少需要：

1. 授权后核对实时图片与任务查询schema，适配文本/图片参考、模型、尺寸和数量。
2. 在计费提交前显示最终参数并由玩家确认；一次意图只提交一次，结果不明时先查原任务。
3. 保存generationId/taskTraceId，跟踪同一任务到终态，完整保留签名URL。
4. 将实际图片纳入现有版本与分支引用，不直接覆盖公共素材。

当前连接器有假MCP协议测试，真实OAuth、账号额度、图片质量和任务跟踪尚未验证。原插件已有这些流程，不等于复制连接地址后Yukino已经获得完整自动生图。[MCP授权规范](https://modelcontextprotocol.io/specification/2025-03-26/basic/authorization)
