# 预制线制作方法

适用引擎：Yukino 5.3，`yukima_script_v1` 剧本与 `yukima_storyline_v1` 故事线。

预制线可以采用“固定主线＋自由活动”：作者写好重要事件、对白、选择和结局，玩家在指定空档自己说话、行动，再返回主线。固定分镜直接播放；自由段使用当前配置的文本模型。它们共用一个存档，不能把自由段放到另一个聊天或另一个不相干的记忆库里。

## 一、先准备剧本

剧本包含世界观、设定集及可选的世界玩法。故事线是世界观中的可选 `storylines`，不是另一个独立剧本，也不是写进主程序的作品专用代码。

可以在任意 Codex 聊天调用本技能，描述世界、人物与故事，让 Codex 整理并导入。自己制作时，先用 `scripts/create_script.py` 生成完整骨架：

```powershell
$skillDir = Join-Path $env:USERPROFILE '.codex\skills\sillytavern-roleplay'
python "$skillDir\scripts\create_script.py" --id my-story --name "我的故事" ".\my-story"
```

此命令只创建文件，不导入、不开始游戏。修改生成的世界观与设定集；完整剧本教程见 `script-creation.md`。人物姓名、年龄、学校、班级、教室、玩家简介与隐式人设应分别填写。人物展示简介不要混入模型规则或存档说明。

单 JSON 剧本直接把故事对象放入 `world.storylines`。目录包可以这样组织：

```text
my-story/
  manifest.json
  world.json
  settings.json
  storylines/short.json
  world-gameplay/...
```

manifest 沿用完整骨架的字段，world.json 增加 `"storylines": ["storylines/short.json"]`。这里的文件路径相对 manifest 所在目录，不得用 `..` 跳出包目录。故事线中的图像 URL 则是舞台资源地址，与这个 JSON 文件路径不同。

## 二、先画出事件顺序

建议先做5–10个节点，确认一条主线能完整走到结局，再增加分支。

```text
开场 → 重要谈话 → 自由活动 → 主线选择 → 收束
                             ├→ 接受方案 → 结局A
                             └→ 暂缓方案 → 结局B
```

每节点只写一个明确的时间、地点与在场人物组合。人物离场、移至别处、跨日，应在旁白和状态里交代，不让离场者继续听见主角说话。自由活动是可游玩的空档，玩家可以自己选择说什么、做什么、是否离开；不要把它写成必须点一个固定选项的假自由。

## 三、最小故事线例子

下面对象可以加到已有春物剧本的 `world.storylines`；其他剧本请改场景、人物姓名和背景键。它有一个无次数限制的自由活动段，玩家自己决定何时继续。

```json
{
  "spec": "yukima_storyline_v1",
  "id": "rain-break-example",
  "version": "1.0.0",
  "title": "雨停之前",
  "description": "一场雨中的短暂停留，可以交谈或自己行动。",
  "start": "arrival",
  "nodes": {
    "arrival": {
      "title": "来到活动室", "scene": "总武高中 · 侍奉部活动室",
      "background": "clubroom-rain", "present": ["雪之下雪乃"],
      "frames": [{"kind":"narration","speaker":"","text":"窗外仍在下雨，她在桌旁整理资料。","expression":"neutral"}],
      "next": "break"
    },
    "break": {
      "title": "自由活动 · 等雨停", "scene": "总武高中 · 侍奉部活动室",
      "background": "clubroom-rain", "present": ["雪之下雪乃"],
      "frames": [{"kind":"narration","speaker":"","text":"雨声暂时没有减弱。你可以自己决定怎样度过这段时间。","expression":"neutral"}],
      "free_window": {
        "description": "可以聊天、看书，或自己到附近走走。",
        "context": "放学后的雨天，玩家在活动室，雪乃正在整理资料。仅按当前存档的关系和真实经历回应，不凭空陪同离场者。主线的雨停与告别尚未发生。",
        "return_text": "【动作】结束自由活动，回到活动室准备告别。"
      },
      "next": "end"
    },
    "end": {
      "title": "告别", "scene": "总武高中 · 侍奉部活动室",
      "background": "clubroom-rain", "present": ["雪之下雪乃"],
      "frames": [{"kind":"narration","speaker":"","text":"雨势渐弱。你收好自己的东西，准备离开。","expression":"neutral"}],
      "ending": "雨后的归途"
    }
  }
}
```

不要只导入这一段故事对象：它需要放进一个完整剧本，并引用有效的设定集人物和资源。已有春物完整示例是 `assets/world-templates/oregairu-script.json`，其中的19节点短篇是 `assets/storylines/oregairu-volume14-short.json`。

## 四、写分镜和选择

`kind` 使用 `narration` 或 `dialogue`。旁白的 speaker 为空；人物对白用设定集准确姓名；主角对白使用 `player`，显示时替换为玩家称呼。`present` 只列本幕确实在场的NPC，不包含主角。对白可用 `audience` 限定实际听众，缺省为本幕在场者与主角。主角内心不能变成人物听见的台词。

每节点1–12分镜。表情使用已有键，如 neutral、soft、serious、thinking、troubled；新增表情先登记同一人物的素材。不要借用其他人物的脸。

一个节点只能有 `next`、`choices`、`ending` 中的一种后续形式。选择例子：

```json
"choices": [
  {"id":"help","text":"【语言】我愿意帮忙，但先把分工说清楚。","target":"planning","set":{"helped":true}},
  {"id":"wait","text":"【动作】先收好资料，明天再确认。","target":"tomorrow"}
]
```

`id` 与目标节点编号必须唯一且有效；一次最多3个选项。`set` 只保存简单字符串、整数或布尔值；`when` 用简单键值相等决定是否显示，例如 `"when":{"helped":true}`。所有可发生的条件组合都必须有出口，不能让玩家所有选项都消失。

## 五、目标阶段与自由方法

`free_window` 放在有唯一 `next` 的节点上，不能同时有 choices 或 ending。没有互动次数上限，也不会显示剩余次数。旧版 max_turns 只兼容读取，播放器不再执行。

| 字段 | 面向谁 | 用途 |
|---|---|---|
| description | 玩家 | 当前可以做什么 |
| context | 模型，隐式 | 当前事实、人物处境和任务背景，不放未来对白 |
| return_text | 玩家动作记录 | 【动作】前缀，采用预设方法时的接续行动 |
| goal | 程序与模型 | 可选的目标、完成条件、边界及汇合节点 |

无 goal 时是普通自由活动；有 goal 时玩家可以自由组织方法，也可点击“沿预设路线推进”。这是两种完成路径，不是先选自由然后被迫回作者唯一答案。`next` 指向预设方法节点；`goal.converge` 指向自由方法完成后的汇合节点。预设节点须真实描述如何补齐尚未解决的问题，不能只说任务完成。汇合节点须保留实际结果，不重演已完成的过程、不替玩家重说一句特定台词。

一个目标阶段示例（嵌在上面 break.free_window 中，先增加 guided、meeting 节点）：

```json
"goal": {
  "title": "和同伴约定下一次可行的见面时间",
  "criteria": [
    {"id":"proposal","description":"实际提出可行的时间与地点"},
    {"id":"agreement","description":"同伴实际回应并同意安排，不能把沉默当同意"}
  ],
  "boundaries": [
    {"id":"coercion","description":"强迫同伴取消安排：按性格拒绝，反复强迫可失去协助或降低实际知情者信任。不同意某个方案、休息或探索不处罚。"}
  ],
  "converge":"meeting",
  "conclude_text":"【动作】按已经确认的约定继续。"
}
```

当前目标与完成状况显示给玩家；人物的详细判断规则隐式传给模型。模型在正常回复中提出 goal_assessment，条件与边界只能引用作者定义的 id，默认条件必须同时引用本轮非内心输入和非心声分镜的真实原文；人物回应类条件可设 source=scene、actor=准确人物名，此时必须引用该人物对玩家可听见的实际对白，不要求玩家复述对方的话。播放器检查引用是否实际存在，随本轮事务保存证据与来源 turn_id；不接受未知条件、无来源的“已完成”、纯内心证据。只在全部条件取得证据后开放“进入收束”，接口同样检查，不能直接请求跳过。条件可以跨多轮累积，并随回溯恢复；重试不重复累积。

语义判定仍由文本模型负责，原文匹配不是对现实真假的完整证明。作者必须试玩假设、梦境、越权许可、强行表白和多人知情范围，不能声称宿主能够确定性判断所有自然语言。

边界应描述现实限制、人物意愿和任务约束，不把闲聊、休息、探索、换一种方法当作违规。人物可按性格拒绝、指出实际后果、提出替代；真实的反复欺骗或强迫可通过原有信任/好感接口产生后果。边界历史保存到当前分支供后续判断，没有全员统一扣分，也没有超时自动惩罚。想要确定性战斗伤害、截止日期结算等规则，应写在剧本世界玩法模块中。

玩家读完当前回应后可继续【语言】【动作】【环境】【内心】输入。阶段没有次数限制；不强迫推主线，但总有可游玩的预设完成路径，达标后有明确汇合点。允许在活动前探索，却不允许凭一句环境输入让未举行的活动已经成功结束。作者主线事件、阶段与关系身份保留宿主控制，实际自由经历、物品和关系温度正常保存。

所有接续与汇合节点必须以旁白开头，交代地点、到场和时间。跨地点返回默认另计5分钟，只适合校内短程；异地长途要由作者补真实耗时。当前例子尚不是完整P5日历模拟，世界玩法可继续扩展。

## 六、效果与素材

`effects` 使用通用 time/items/relations/threads 能力，必须填写实际事件 reason。时间单位为分钟，一次最多7天；物品有持有者与数量；关系身份不能由好感分数直接确立。确认恋爱需在同一节点包含主角表达与对方明确同意的对白；不能把拒绝写成接受。

```json
"effects": [{"type":"time","minutes":15,"reason":"走到约好的地点并等待同伴"}]
```

背景使用已登记的键，也可在故事线顶层声明本线资源：

```json
"backgrounds": {
  "spring-room": {"url":"/storyline-backgrounds/clubroom-spring-rain.png","name":"春雨中的侍奉部"}
}
```

相应图片须实际位于舞台的 `assets/galgame/storyline-backgrounds/`，或按共享库格式登记 `/media/browser/assets/文件名.png`。目录包导入不会自动复制任意图片，要由技能同时登记资源。检查画风、人物身份、季节和场景；不能等玩家读到该幕才发现资源不存在。固定主线不主动预测生图；自由段沿用现有动态生图和候选配额。

## 七、检查、导入与试玩

```powershell
$libraryRoot = Join-Path $env:USERPROFILE 'Documents\Codex\roleplay-library'
python "$skillDir\scripts\worlds.py" --root "$libraryRoot" validate-script ".\my-story"
python "$skillDir\scripts\worlds.py" --root "$libraryRoot" import-script ".\my-story"
```

validate-script 不写入原库；import-script 才导入。建议先用一个空的临时库试导入和试玩，再导入原库。不要通过附着快照或改存档JSON，把老周目无声变成新路线。

发布前逐项检查：

- 每条路线都能走到明确结局，条件选择没有死路。
- 人物引用、实际在场与听众正确，离场后没有跨地点回应。
- 自由段可以持续输入、保存和读取；失败与重试不重复写入目标证据。
- 预设方法与自由达标都能汇合；不达标不能跳到收束，合理探索不受罚。多人可沉默或互相接话。
- 回溯到自由段前会排除后来自由行动，原分支保留。
- 场景资源能加载，立绘对应本人；回看与导出保留各人的署名。
- 固定版旧档仍使用冻结内容；更改 version 后只让新档采用新路线。

## 八、版本和存档

故事 id 稳定，内容修改后提升 version。完整故事和内容哈希冻结在存档中，阅读位置、已选记录、阶段目标证据、边界历史与实际经历随分支保存。回溯使用真实节点快照，不凭父档最新状态拼过去记忆。更新剧本只影响新档；旧档继续旧版，不能静默给旧档塞入未来事件或替换主线。

低层协议与API详见 `storylines.md`。存档继承压缩记忆仍是独立实验，本功能没有替换原记忆系统。


### 故事线自己的时间起点

世界观 `world.time` 提供标准时间规则；预制线可加 `time_start` 指定日期/时刻/相对时代标签，只在首次开始时生效，之后与自由段共用同一时钟。节点通过 `effects` 的 `type=time, minutes, reason` 推进；不能直接写日期跳过校验。规则、时间与模块内部状态随节点快照回溯，已有档不因改剧本而跳日。完整协议见 [time-system.md](../skills/sillytavern-roleplay/references/time-system.md)。


### 5.6 播放与条件检查

读完当前节点最后一段可见分镜后才可推进。角色心声不占阅读推进位置；刷新恢复已保存位置。目标自由段达标后直接进入 `goal.converge`，不重播预设方法的对话。导入检查可达的“节点+标记”状态，拒绝所有选项隐藏或条件状态无法到达结局的路线；状态组合超过10,000需要简化。预制背景在实际访问后加入分支画廊与公共图库，可按 [调整画面](../skills/sillytavern-roleplay/references/image-adjustments.md) 另存新版。旧档继续冻结路线，不自动升级故事内容。
