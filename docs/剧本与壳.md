# 剧本与壳

Yukino 分为两层：**壳是主程序，剧本是用户可以自己编写、导入和分享的内容包**。主程序提供浏览器舞台和通用接口；剧本决定世界是什么样、有哪些人物、从哪里开始，以及有哪些玩法。

## 两层分别负责什么

| 内容 | 壳：主程序 | 剧本：内容包 |
| --- | --- | --- |
| 世界与人物 | 读取、校验、图鉴和模型上下文 | 世界背景、人物卡、地点、规则、主角预设 |
| 开场与故事 | 展示分镜、接收输入、记录真实进展 | 开场场景、人物判断、初始关系、事件前提 |
| 玩法 | 加载器、版本管理、通用状态接口和操作界面 | 委托、战斗、探索、经营等模块的实际规则代码 |
| 时间与物品 | 分支内保存时间、物品、事件与关系，检查状态变化 | 起始时间、初始物品、消耗和完成条件 |
| 图片与音乐 | 展示、切换、生成管道、预测配额和缓存 | 人物和场景素材、外貌参考、氛围说明 |
| 记忆与存档 | 独立分支记忆、回溯、导入导出、回收站 | 初始设定；不把预测和未发生事件写成玩家经历 |

新增一个玩法不需要先在主程序里写一个对应的“战斗类”或“委托类”。剧本携带代码，主程序按约定调用，并统一显示记录卡片与动作按钮。与通用接口兼容的模块可以随新剧本导入；模块需要主程序尚未提供的能力时，仍须扩展接口或升级主程序。

## 剧本包长什么样

```text
my-story/
  manifest.json                 包入口
  world.json                    世界观、开场、初始时间
  settings.json                 人物、地点、物品、规则和事件
  world-gameplay/
    rules.module.json           模块 ID、版本、能力和代码路径
    rules.py                    剧本自己的玩法规则
```

```json
{
  "spec": "yukima_script_v1",
  "world": "world.json",
  "setting_sets": ["settings.json"],
  "world_gameplay": ["world-gameplay/rules.module.json"]
}
```

所有路径相对于根 `manifest.json`。旧的单文件 JSON 剧本仍支持内嵌世界观、设定集，以及可选的玩法代码。没有玩法模块也可以正常游玩。

玩法模块的基本声明：

```json
{
  "id": "my-rules",
  "name": "探索记录",
  "version": "1.0.0",
  "api_version": 1,
  "runtime": "python-restricted-v1",
  "code_file": "world-gameplay/rules.py",
  "config": {},
  "capabilities": [],
  "dependencies": {}
}
```

模块定义 `run(request)`，处理初始化、界面、模型上下文和实际事件。它返回自己的状态、可用动作及可选世界状态效果；主程序负责核对并与本轮剧情一起提交。玩法结果已经结算后，文本模型不能重新决定胜负、重复发奖励或重复扣时间。

当前模块使用受限 Python 运行时：允许纯计算，不允许文件、网络、系统命令和任意依赖包；不是任意代码或任意网页界面的执行器。每个剧本最多 12 个模块，单次调用有时间、执行量和内存限制。完整协议、示例与限制见 [世界玩法接口](../skills/sillytavern-roleplay/references/gameplay.md)。

## 创建、检查和导入

需要 Python 3.10+。在项目根执行：

```powershell
# 生成到新的空目录；生成的内容是可修改的原创示例，不会自动导入。
python -B -X utf8 skills/sillytavern-roleplay/scripts/create_script.py my-story --id my-story --name "我的故事"

# 修改 world.json、settings.json；需要玩法时添加代码并登记 manifest。
# 校验不改变正式资料库。
python -B -X utf8 skills/sillytavern-roleplay/scripts/worlds.py --root database/roleplay-library validate-script my-story

# 检查成功后导入，刷新浏览器剧本选择页。
python -B -X utf8 skills/sillytavern-roleplay/scripts/worlds.py --root database/roleplay-library import-script my-story
```

首次运行 `launch.py --demo` 会建立项目资料库。校验检查资料引用、模块 ID 与版本、依赖、规则代码、初始化及界面返回值；不会自动检查所有设定矛盾或素材是否足够。详细字段与素材登记见 [创建剧本](创建剧本.md)。

也可以在 Codex 聊天引用本项目技能后说：

> 在本项目里创建原创剧本《海边调查》。整理世界观、人物与地点、两个开场，并添加由剧本携带的调查模块。模块记录线索及事件条件，人物是否透露信息应符合性格与关系。先校验，再导入；不要开始游戏，也不要修改现有存档。

角色卡可使用 SillyTavern PNG/JSON，或直接提供文字设定让助手整理。主角卡另行导入；玩法不是角色卡里的现实工具指令。作者需要自己准备有权使用的美术，文字剧本导入不会自动补齐图片。

## 更新剧本怎样影响存档

设定快照、模块版本和代码哈希随存档固定。更新目录里的剧本不会自动重写旧故事；旧存档继续使用自己的版本。希望体验新版玩法时，先导入新包，再在旧档的“手记”里选择“在新分支中启用新版玩法”。原档保留，升级之前的回溯节点继续使用原版本。

每个存档单独保存模块状态、关系、时间、物品、事件和记忆。回溯只继承选定节点之前确实发生的内容；图库共享不等于剧情记忆共享。不要删除仍被旧档引用的历史玩法代码。

## 迁移与运行依赖

剧本包可以与主程序分开分享，接收者需要兼容其格式、运行时和 API 版本的 Yukino。主程序本身是 Python 服务与浏览器页面；调用技能主要用于辅助创建、整理和维护。

当前文本客户端专门适配 DeepSeek Flash，动态生图仍使用支持原生生图的 Codex CLI 常驻服务。关闭生图后可以使用预备素材继续文本游玩。文本与生图虽然分开，尚未实现任意服务的通用配置接口。

共享剧本不包含玩家自己的存档、记忆、API Key 或登录凭据。仓库的 `examples/demo-library` 只提供一个预写演示，私人运行库是被 Git 忽略的 `database/roleplay-library`。
